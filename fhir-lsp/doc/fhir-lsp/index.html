fhir-lsp: a language server for the FHIR languages🔗ℹ

One Language Server Protocol server for FHIR Shorthand (.fsh), CQL (.cql), the FHIR Mapping Language (.fml, .map), VCL (.vcl) and FHIRPath (.fhirpath). As you type, each document’s problems are published to the editor exactly as the language’s own compiler reports them, positioned on the line and column; an FSH file is checked as part of its project (its sushi-config.yaml and the other files beside it), so a profile rule that breaks an example two files away is reported there. Each language package is loaded when a document of its kind is opened, so the server runs with whichever languages are installed. Part of the fhir family.

1 Quick start🔗ℹ

1. Install the server and the languages you write (the packages are not on the Racket package server yet; clone the repositories side by side):

raco pkg install --link --auto fhir/fhir fhir/fhir-spec fhirpath vcl fhir/fhir-tx fhir/fhir-validation cql fml fsh fhir/fhir-lsp

raco fhir-lsp languages        # fsh .fsh / cql .cql / fml .fml .map / vcl .vcl / fhirpath .fhirpath

2. Point your editor at it. The command is raco fhir-lsp, speaking the protocol on stdin and stdout.

  • VS Code: with a generic LSP client such as Generic LSP Client or LSP Proxy, add a server with command raco, arguments ["fhir-lsp"], for the languages fsh, cql, fml, vcl; associate the file extensions with those language ids under files.associations if the extension does not already.

  • Neovim (0.8+), in init.lua:

    vim.filetype.add({ extension = { fsh = "fsh", cql = "cql", fml = "fml", map = "fml", vcl = "vcl" } })

    vim.api.nvim_create_autocmd("FileType", {

      pattern = { "fsh", "cql", "fml", "vcl" },

      callback = function()

        vim.lsp.start({ name = "fhir-lsp", cmd = { "raco", "fhir-lsp" }, root_dir = vim.fs.root(0, { "sushi-config.yaml", ".git" }) })

      end,

    })

  • Emacs (29+, eglot):

    (add-to-list 'eglot-server-programs '((fsh-mode cql-mode fml-mode vcl-mode) . ("raco" "fhir-lsp")))

    with a mode per extension (define-derived-mode from prog-mode and auto-mode-alist entries are enough).

3. Open a file. A mistake is underlined where it is, with the message the command line would print; in an FSH project, an example that breaks a profile rule is reported on the instance rule and names the profile rule.

Without an editor, raco fhir-lsp check ig/input/fsh/bp.fsh prints what the server would publish, in the family’s diagnostic format (--format text|json|outcome), and exits 1 when any problem is an error.

2 What it does🔗ℹ

language

  

on open, change and save

fsh

  

the whole project compiled with the document's text in place of the file on disk: parse errors, unknown element paths at their rule, entities that fail, every example validated against the project's profiles (positioned at the instance rule, naming the profile rule); diagnostics for other files of the project are published too

cql

  

parse errors; every definition translated, each failure at its define

fml

  

parse errors; the map checked against its structures (an element the type lacks, a value that cannot go into its element, a wrong group call, a required target never assigned)

vcl

  

the expression parsed and compiled to a compose

fhirpath

  

the expression parsed

What the server knows about a language comes from that language’s own package: each provides a <id>/support module, a fhir/lang/support value with its diagnostics, project files, outline, hover, definition, completion and tools, tested with the language. The server holds only the protocol and the open documents, builds a document’s project (the support’s files, open ones as the editor holds them) and hands it to the support. For FSH, two more, read from the text rather than a parse (so they work while a document does not parse yet): hover on a rule’s element path shows the base type’s definition of that element (path, cardinality, types, short and definition from the core snapshot; the base is the document’s Parent or InstanceOf, followed through the project’s own profiles and aliases); hover on a name shows the declaration it refers to. Go to definition on a name (a Parent, an InstanceOf, a value set in a binding, an alias, a RuleSet in an insert, an invariant, an instance in a Reference) opens the declaration in this project, found by name, id or canonical, across the project’s files as the editor holds them.

Completion (FSH): at the start of a line the entity and metadata keywords; after Parent: or InstanceOf: the FHIR types and the project’s profiles, extensions and models; after from its value sets and aliases, after insert its rule sets, after obeys its invariants; after * and a dotted prefix, the base type’s elements at that path with their cardinality, types and short description; after a path, the flags and rule keywords. Document symbols: the document’s declarations as an outline.

For CQL and FML the same three work from the declarations the text shows, without a parse: the outline lists a library’s includes, value sets, code systems, parameters, context and defines (a map’s uses, imports, concept maps and groups); hover on a name shows its declaration, and go to definition jumps to it within the document (a quoted CQL name is the text inside its quotes) or to the file beside it that an include names (X-v.cql, X.cql, or the one whose library line declares X) or an FML imports names (the map whose map "url" line declares it); completion offers the document’s declared names and the language’s keywords that start with what is typed (inside quotes, names only).

Diagnostics are computed off the protocol loop: an open, change or save updates the stored text at once (so hover and completion see it) and the diagnosing runs in a worker thread; when another edit arrives before it finishes, the older result is dropped, so a large project’s compile never blocks the editor or publishes stale findings.

Protocol: initialize, initialized, shutdown, exit, textDocument/didOpen, didChange (full text), didSave, didClose, textDocument/hover, textDocument/definition, textDocument/completion, textDocument/documentSymbol, and textDocument/publishDiagnostics back. Any other request is answered with method-not-found; other notifications are ignored.

3 Limits🔗ℹ

  • Hover, definition, completion and symbols read the text, not a parse: a name is the word under the cursor, an FSH element is looked up in the base type’s core snapshot (not the profile’s or a dependency’s constraints). Element-path completion and project-wide definition are for FSH; CQL and FML names complete and resolve within one document, and includes and imports reach the files beside it. No formatting, rename or references.

  • An FSH document is recompiled with its project on every change; on a large project (mCODE: hundreds of entities) that takes seconds, during which the previous diagnostics stand.

  • Positions are the compilers’ positions: a CQL translation error without one, or a problem in a file the project reports on without a line, lands on the first character.

  • Documents are read as whole texts (full synchronisation); incremental changes are not accepted, which every editor negotiates from the capabilities.
