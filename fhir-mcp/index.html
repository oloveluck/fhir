fhir-mcp: the FHIR family as tools for an agent🔗

A Model Context Protocol server over the family. Every FHIR operation the installed packages implement is a tool whose input schema is its OperationDefinition’s parameters: fhir_validate, fhir_expand, fhir_validate-code, fhir_lookup, fhir_translate, fhir_snapshot, fhir_transform, fhir_evaluate-measure, fhir_sql-run and the rest. The languages add their own: diagnose_file (any file of the five languages, as the family’s positioned diagnostics), fsh_check (a project: compile and validate every example), fsh_compile, fsh_decompile, cql_elm, cql_evaluate, vcl_valueset, fhirpath_evaluate; and the packages in context answer fhir_element (what an element is) and fhir_find (which profile, value set or extension is called what), so an agent writing a profile can look things up the way an author reads the specification. An agent writing FSH, CQL or maps gets the same checks a person gets at the command line, and FHIR data in and out as JSON. Part of the fhir family.

1 Quick start🔗

1. Install the server and whatever operations and languages you want it to offer (the packages are not on the Racket package server yet; clone the repositories side by side):

raco pkg install --link --auto fhir/fhir fhir/fhir-spec fhirpath vcl fhir/fhir-tx fhir/fhir-validation cql fml fsh fhir/fhir-lsp fhir/fhir-mcp

raco fhir-mcp tools | head -c 600        # the tools and their schemas

2. Point an agent at it. The command is raco fhir-mcp, speaking the protocol on stdin and stdout, one JSON line per message. For Claude Desktop or Claude Code, an entry in the MCP configuration:

{

  "mcpServers": {

    "fhir": {

      "command": "raco",

      "args": ["fhir-mcp", "--package", "hl7.fhir.us.core-6.1.0.tgz", "--package", "hl7.fhir.r4.core.tgz"]

    }

  }

}

--package names the FHIR packages profiles and value sets resolve from (a .tgz or a file in fhir-spec, repeatable, in order); --data <dir> is a directory of resources the operations read as their data source (what $expand finds a ValueSet in, what a measure runs over).

3. Try a tool from the shell. raco fhir-mcp call runs one tool with JSON arguments and prints its text:

$ raco fhir-mcp call vcl_valueset '{"vcl": "(http://loinc.org)(85354-9;55284-4)"}'

{"resourceType":"ValueSet","url":"http://fhir.org/VCL?v1=(http://loinc.org)(85354-9;55284-4)", ...}

$ raco fhir-mcp call fhir_validate '{"resource": {"resourceType": "Patient", "gender": "florp"}}' --package hl7.fhir.r4.core.tgz

{"resourceType":"OperationOutcome","issue":[{"severity":"error","code":"code-invalid", ...}]}

$ raco fhir-mcp call fsh_check '{"directory": "ig/"}'

The exit code is 1 when the tool reports an error (an OperationOutcome with errors, diagnostics with an error, a missing argument).

cql, resources, parameters

vcl_valueset

  

vcl

fhirpath_evaluate

  

expression, resource

  

the result collection as JSON

fhir_element

  

type, path

  

an element's definition from a type or profile in the packages: cardinality, types, binding, short, definition (valueQuantity finds value[x]); without a path, the type's top-level elements

fhir_find

  

query, resourceType, limit

  

profiles, extensions, value sets, code systems, operations and search parameters in the packages whose id, name or url contains the query

fsh_decompile

  

resource

  

FHIR JSON to FSH (a StructureDefinition, ValueSet or CodeSystem idiomatically; anything else an Instance)

data_resources

  

type, id

  

the ids of a type in the data source, or one resource

Which operations appear depends on the packages installed: fhir ($snapshot), fhir-validation ($validate), fhir-tx (the terminology operations), fml ($transform), cql ($evaluate-measure), sql-on-fhir ($sql-run, $sql-export). Two operations sharing a code are told apart by resource type (fhir_Patient_everything).

3 Resources and prompts🔗

Besides tools the server answers resources/list, resources/templates/list and resources/read: fhir://guide/authoring, fhir://guide/cli and fhir://guide/serving are the family’s how-to guides as markdown (the repository’s skills, served when the package is installed from the repository), fhir://packages the FHIR packages in context, and fhir://definition/{kind}/{ref} any StructureDefinition, ValueSet, CodeSystem, StructureMap or ConceptMap in them by id, name or canonical url, as JSON. prompts/list and prompts/get give three starting points an agent fills with arguments: fsh-profile (a base and requirements: write the profile, check it with the tools, prove it with a conforming and a violating instance), fsh-instance (a profile and a scenario) and fix-project (a project directory: fix every diagnostic at its line). Each carries the authoring guide when it is at hand.

4 Limits🔗

  • No sampling or subscriptions; one request at a time; stdio only.

  • A language tool runs in the server’s process with the context given at start; an FSH project is checked from disk.

  • The protocol version answered is 2024-11-05; clients that insist on a newer one still work with the same methods.
