fhir: the foundation🔗ℹ

The package the rest of the family builds on: the typed node model and its registry, the primitive types, JSON in and out, the FHIR NPM package reader, StructureDefinition tooling (an index over packages, snapshot generation), FHIR operations as procedures, data sources, and the diagnostics every language reports. The R4, R5 and R6 type towers are generated from the HL7 specifications; R6 comes with #lang fhir/r6, where a resource is a form checked as it compiles.

The other packages: fhir-spec (the HL7 packages, data only), fhir-tx (terminology), fhir-validation (the validator), fhir-server (servers generated from Implementation Guides), and the languages fhirpath, cql, fsh, vcl, fml and sql-on-fhir, each its own package and repository.

1 Quick start🔗ℹ

1. Install. The packages are not on the Racket package server yet; clone the repository and install from source:

raco pkg install --link --auto fhir/fhir fhir/fhir-spec

fhir depends on nothing but base; fhir-spec is the data the tools read.

2. Write a resource. In #lang fhir/r6, each top-level form builds a typed node of an R6 resource or datatype: a list field takes several values, a complex field a nested form, a choice element its concrete name (deceasedBoolean), a primitive a literal.

"patient.fhir6"

#lang fhir/r6
(Patient
 (id "example") (active #t) (gender "male") (birthDate "1974-12-25")
 (name (HumanName (use "official") (family "Chalmers") (given "Peter" "James"))))

3. Run it. racket patient.fhir6 prints the resource as JSON. A mistake is a compile error: an unknown or duplicate field, a missing required field, a bad primitive lexeme ((birthDate "1974-13-40")), or a code outside a required binding ((gender "florp") lists the valid codes).

2 Using it🔗ℹ

2.1 Resources as modules🔗ℹ

(require "forms.fhir6") gives resources (the typed nodes), (->nodes) and (->json) (jsexprs). R4 and R5 are schema-only towers: (require fhir/r4/schemas) or fhir/r5/schemas registers their types for from-json, FHIRPath and the validator, with no forms. fhir/r4/operations, fhir/r5/operations and fhir/r6/operations carry each version’s OperationDefinitions as data.

#lang fhir/sd is the small in-Racket profile: (profile Name #:base Base (field min max) ...) defines a form like its base with narrowed cardinalities, checked at compile time (a profile may only narrow). Full profiles are written in FSH, the fsh package.

#lang fhir/sd
(profile USCorePatient #:base Patient (name 1 *) (gender 1 1))
(profile VIPPatient #:base USCorePatient (name 1 1))

2.2 JSON in and out🔗ℹ

Load a tower, then from-json gives a typed node and node->jsexpr gives it back. Strict from-json returns an err for an unknown element; lenient parsing skips it. read-fhir-json keeps each number’s lexeme, so "1.50" survives a round trip.

(require fhir/r5/schemas fhir/serialize/from-json fhir/serialize/to-json fhir/serialize/read-json
         fhir/model/node fhir/model/leaf fhir/result/result)
(define p (ok-value (from-json (call-with-input-file "patient.json" read-fhir-json) #:lenient? #t)))
(fhir-type p)                                                 ; 'Patient
(node-str p 'gender)                                          ; "male"
(pv (fhir-ref (car (listify (fhir-ref p 'name))) 'family))   ; "Chalmers"
(node->json-string p)                                         ; decimals as written

2.3 Operations as procedures🔗ℹ

An operation is applied by reference to its OperationDefinition, with its parameters as keywords; the subject is the first argument; ~> threads a value through several. Loading a package’s operations module registers what it implements. A failure raises exn:fail:operation with an OperationOutcome; apply-operation/outcome returns it instead.

(require fhir/operation fhir/data-source
         (only-in fhir/conformance/operations ensure-valid)      ; fhir-validation
         (only-in fhir/terminology/operations $expand)           ; fhir-tx
         (only-in fml/operations))                               ; fml
(apply-operation "StructureMap/$transform" qr #:srcMap fml-text)
(define transform (operation "StructureMap/$transform"))
(~> qr (transform #:srcMap fml-text) (ensure-valid))
(apply-operation "ValueSet/$validate-code"
                 #:url "http://hl7.org/fhir/ValueSet/administrative-gender"
                 #:system "http://hl7.org/fhir/administrative-gender" #:code "female")

Context comes from two parameters: current-data-source, where an operation finds resources (in memory, a directory, or a server’s store), and current-sd-packages, the FHIR packages profiles and value sets resolve from (an IG, its dependencies, then core).

(parameterize ([current-data-source (resources->data-source clinic)]
               [current-sd-packages (list "hl7.fhir.us.core-6.1.0.tgz" "hl7.fhir.r4.core.tgz")])
  (ensure-valid observation #:profile "http://example.org/StructureDefinition/screening-blood-pressure"))

2.4 Command line🔗ℹ

raco fhir regen [r6|r4|r5|all]

  

regenerate the type towers from fhir-spec

raco fhir check [r6|r4|r5|all]

  

the committed towers match a fresh regeneration

raco fhir roundtrip file.json [Type]

  

parse and serialize one resource

raco fhir roundtrip-tck [r4|r5]

  

parse and serialize the whole core corpus

raco fhir snapshot sd.json

  

generate a StructureDefinition's snapshot

-h on the tool or any command prints usage and exits 0; a usage error or missing file is one line on stderr, exit 2; drift or a failed parse exits 1. Every language’s tool reports problems as file:line:col diagnostics with the source line and a caret, or as JSON or an OperationOutcome with --format json|outcome.

3 Limits🔗ℹ

  • Forms exist for R6 only. R4 and R5 are schema towers for parsing, navigation and validation; there is no #lang fhir/r4 or fhir/r5.

  • Snapshot generation covers the differential merge, named slices and datatype expansion; not reslicing, discriminator inference, [x] slice expansion or contentReference. The HL7 snapshot cases stand at 80/80 paths, 476/478 cardinalities, 235/236 types.

  • Compile-time bindings cover required bindings on code elements whose value set enumerates its codes or includes a whole system from the same package; filters, imports and excludes fail open.

  • JSON only: no XML anywhere in the family.

fhir/operation🔗ℹ

 (require fhir/operation) package: fhir

A FHIR operation is an OperationDefinition plus an implementation, with nothing about HTTP: a procedure whose keyword arguments are the definition’s parameters. Applying is (op subject #:name value ...): the subject is the resource the operation applies to, a Parameters resource may carry inputs, a list gives several values; strings are converted for integer, decimal and boolean parameters; an unknown keyword is an error listing the parameters. The result is the return resource, or a Parameters of the outputs. The packages register their operations when loaded: $validate and ensure-valid (fhir-validation), $expand, $validate-code, $lookup, $translate (fhir-tx), $transform (fml), $evaluate-measure (cql), $sql-run (sql-on-fhir), $snapshot (here).

(apply-operation "StructureMap/$transform" qr #:srcMap fml)
(define transform (operation "StructureMap/$transform"))
(~> qr (transform #:srcMap fml) (ensure-valid) ($snapshot))

fhir/registry🔗ℹ

 (require fhir/registry) package: fhir

The module system as the FHIR registry. A #lang fsh module registers its profiles, value sets and code systems when it is instantiated, a #lang vcl module its value set, a #lang fml module its StructureMap; every resolver in the family looks here between the current data source and the packages (profiles for #:profile and meta.profile, a map’s uses, the terminology resolver, $transform #:source), so requiring a module is enough for what it defines to be found by canonical, with no data source to set up.

fhir/parallel🔗ℹ

 (require fhir/parallel) package: fhir

procedure

(parallel-map fn    
  items    
  [#:workers workers    
  #:setup setup]) → list?
  fn : (list/c module-path? symbol?)
  items : list?
  workers : exact-positive-integer? = (default-workers)
  setup : (or/c module-path? #f) = #f
Maps the function fn names (a module path and an export) over items on every core and answers the results in order. The workers are racket processes of their own (threads share one core, and places share one heap, whose collections stop every place), so the function is named, not passed: each worker instantiates setup (a type tower, say) and then the function’s module. Items and results are written and read as S-expressions, so they must be readable data; the sharing wins when what crosses is small next to the work — hand a worker a path or a shard number rather than the data. Items are dealt one at a time as workers finish. With one worker the function runs in-process.

procedure

(default-workers) → exact-positive-integer?

One per core, or FHIR_WORKERS from the environment (1 keeps everything in-process).
