9.3

fhir: the foundation🔗

FHIR is the standard most health systems use to exchange data. A patient, a lab result, a prescription are each a small JSON document called a resource, and the standard says exactly what each one may contain: which fields, how many of each, what a date or a code must look like.

Every tool in this family has to do the same few things with resources: read one, check that each value is what FHIR says it must be, write it back out unchanged, and say where a mistake is. This package is where that is done, once, for the three FHIR versions in use (R4, R5 and R6). The languages and tools (fsh, cql, fml, the validator, the server) are built on it.

You will rarely use it directly. If you only use the command-line tools, it is installed with them and works underneath; If you only use the command-line tools is all you need from this page. If you write programs in Racket, this is the library you program against, and the rest of the page is for you.

Part of the fhir family of FHIR languages and tools.

1 What you can do with it🔗

  • Read the guides from the command line: raco fhir guide prints the family’s guides, one per language and one for FHIR itself (If you only use the command-line tools).

  • Start a small project from a template and check every language file in a folder in one run: raco fhir new pipeline and raco fhir check-files (Language files as modules).

  • Write a resource as a checked form: in #lang fhir/r6 a misspelt field, a date that is no date or a code FHIR does not allow stops the file from building (A first example).

  • Read FHIR JSON in a program, look inside it, and write it back with every number as it was written (Reading and writing FHIR JSON).

  • Call FHIR’s operations as functions: $validate, $expand, $transform and the rest, with no server (Operations as functions).

  • Let definitions find each other by address: a profile, a value set or a map is found by its url wherever it lives (How definitions and data are found).

  • Report problems the way the family does: one value, shown as file:line:column text, as JSON or as a FHIR resource (Reporting problems).

2 If you only use the command-line tools🔗

Install the tools as the family’s front page describes. This package comes with them; there is nothing to set up. Three things on this page are worth knowing.

The guides. raco fhir guide lists them, and raco fhir guide <topic> prints one. They are written to be read quickly: a cheat sheet, a worked example, the common problems.

$ raco fhir guide

fhir  FHIR for agents: which resource holds which fact, the shapes that recur (codes, quantities, references, choice elements), the usual code systems, links to the specification

workspace  The workspace: files, the tools (write, check, run, query, explain, describe, apply, stage, commit), which language for which question, workspace.yaml

fsh  FHIR Shorthand: profiles, extensions, value sets, examples; cheat sheet, worked example, links to the FSH specification

cql  Clinical Quality Language: patient logic and cohorts; cheat sheet, worked example, links to the CQL specification and reference

…

A guide’s examples can be saved as files: raco fhir guide racket --blocks lists the code blocks of the racket guide, and raco fhir guide racket --block minimal > main.rkt saves the one named minimal. A block is asked for by its name or its number.

One way of reporting a mistake. Every tool in the family says where a problem is in the same form: the file, the line and the column, the message, then the line itself with a marker under the place. Here is the CQL tool refusing a misspelt function:

Intake.cql:6:15: cql compile error: in define "Age": unknown function 'AgeInYear' (did you mean `AgeInYears` or `AgeInYearsAt`?)

 6 | define "Age": AgeInYear()

   |               ^^^^^^^^^

The languages’ tools and the validator take --format json or --format outcome to print the same report for a program to read (Reporting problems).

The same exit codes. A tool exits with 0 when all is well, 1 when it found a problem in what you gave it, and 2 when it was called wrongly (an unknown option, a file that is not there). Every tool prints its usage with --help.

The other commands of raco fhir are in The command line.

3 A first example🔗

This example writes one resource and has it checked. It needs Racket.

1. Install as the front page describes. Of the packages it installs, this page needs two: fhir (this one, which depends on nothing but Racket itself) and fhir-spec (the FHIR specification as HL7 publishes it, which the tools read).

2. Write a resource. FHIR resources are usually written as JSON. Here you write one as a form instead: the same content, with parentheses, in a file whose first line names the FHIR version. This is patient.fhir6:

"patient.fhir6"

#lang fhir/r6
(Patient
 (id "example") (active #t) (gender "male") (birthDate "1974-12-25")
 (name (HumanName (use "official") (family "Chalmers") (given "Peter" "James"))))

Each pair of parentheses is one field of the resource and its value. A field that holds a structure, such as a name, takes a form of that structure’s type (HumanName). A field that repeats takes all its values at once (given).

3. Run it. The file is a program that prints the resource as JSON:

$ racket patient.fhir6

{"active":true,"birthDate":"1974-12-25","gender":"male","id":"example","name":[{"family":"Chalmers","given":["Peter","James"],"use":"official"}],"resourceType":"Patient"}

4. Make a mistake. FHIR allows four values for a patient’s gender. Write (gender "florp") and the file no longer builds; the message says where the mistake is (file, line and column) and lists the values that are allowed:

$ racket patient.fhir6

patient.fhir6:3:36: Patient: "florp" is not in the required value set for Patient.gender (http://hl7.org/fhir/ValueSet/administrative-gender); valid codes: (female male other unknown)

  in: "florp"

  …

The same happens for a field FHIR does not define (Patient: unknown field Patient.actve), a date that is no date (Patient: invalid date value: "1974-02-30"), a required field left out, or a field given twice. Nothing has to run for these to be found: they are caught when the file is built.

5. Use it from a program. The file is also a Racket module. Another program requires it and gets the resource as a value:

(require "patient.fhir6" fhir/model/leaf)
(define p (car resources))
(node-str p 'gender)        ; "male"
(->json)                    ; the same resources as JSON data

4 The command line🔗

raco fhir is this package’s command. Half of it is for anyone, half for people who maintain the package.

raco fhir new pipeline <dir>

raco fhir snapshot sd.json

raco fhir roundtrip-tck [r4|r5]

  

for maintainers: read and write back every resource HL7 publishes for that version

raco fhir regen [r6|r4|r5|all]

  

for maintainers: regenerate the FHIR types from the specification

raco fhir check [r6|r4|r5|all]

  

for maintainers: the generated types on disk equal a fresh generation

roundtrip reads strictly, with the R6 types: an element FHIR does not define is refused.

$ raco fhir roundtrip odd.json

roundtrip: parse failed: Patient: unknown field colour (see https://build.fhir.org/patient.html#Patient)

To check a resource against FHIR’s rules in full (allowed codes, required fields, a profile), use raco fhir-validate, the validator’s own command.

snapshot needs the fhir-spec package, and looks the profile’s base up in the R5 specification. It prints the profile again with every element spelt out: a profile that changes one element of Patient comes back with all 45.

Exit codes are the family’s: 0, 1 for a problem found (a resource that does not parse, generated files that differ), 2 for a wrong call, which prints one line and the usage:

$ raco fhir roundtrip nope.json

raco fhir roundtrip: no such file: nope.json

usage: raco fhir roundtrip <file.json> [Type]

Turning FHIR JSON into FHIR Shorthand is the fsh package’s (raco fsh --decompile).

5 Resources as forms🔗

A form is a resource written so that it is checked as it is built. You have seen one in A first example; this section is the rules.

  • One form per resource or structure. (Patient …), (Observation …), (HumanName …), (Coding …): every R6 resource and datatype has a form of its name. A file may hold several top-level forms.

  • A simple value is a literal: a string, a number, #t or #f.

  • A repeating field takes all its values in one form: (given "Peter" "James"). Writing the field twice is an error that says so.

  • A choice is written by its full name. Where FHIR lets a value be one of several types (deceased[x] is a boolean or a date and time), write the one you mean: (deceasedBoolean #f).

  • What is checked: unknown and duplicate fields, missing required fields, how many values a field may have, the type of a nested form, the text of every date, time, code, url and number, and codes that FHIR restricts to a fixed list.

A file in #lang fhir/r6 provides resources (the resources as typed values), (->nodes) (the same list) and (->json) (as JSON data). Run directly it prints the JSON.

5.1 Narrowing a type: #lang fhir/sd🔗

A profile is a stricter version of a type for one setting: "here, every patient has a name and a gender". #lang fhir/sd is a small way to say that in Racket:

"us.sd"

#lang fhir/sd
(profile USCorePatient #:base Patient (name 1 *) (gender 1 1))
(profile VIPPatient #:base USCorePatient (name 1 1))

Each line of a profile gives a field its least and greatest number of values (* is "any number"). The profile becomes a form of its own, which checks its rules and then builds the base resource:

(require "us.sd" fhir/r6/types)
(USCorePatient (gender "female") (name (HumanName (family "A"))))    ; a Patient
(USCorePatient (gender "female"))
; error: USCorePatient: missing required field USCorePatient.name

A profile may only narrow. One that loosens its base is refused where it does so:

loose.sd:3:20: profile: name: min 0 loosens base min 1 (a profile may only narrow)

This covers how many values a field has, nothing more. Real profiles (fixed values, bindings to value sets, slices, invariants) are written in FHIR Shorthand, with the fsh package.

6 Reading and writing FHIR JSON🔗

Most programs meet FHIR as JSON from somewhere else. Reading it gives a typed node: a value that knows its FHIR type and holds each field already checked.

(require fhir/r5/schemas fhir/serialize/from-json fhir/serialize/to-json fhir/serialize/read-json
         fhir/model/node fhir/model/leaf fhir/result/result)
(define js (call-with-input-file "patient.json" read-fhir-json))
(define p (ok-value (from-json js)))
(fhir-type p)                                                 ; 'Patient
(node-str p 'gender)                                          ; "male"
(pv (fhir-ref (car (listify (fhir-ref p 'name))) 'family))   ; "Chalmers"
(node->json-string p)                                         ; the JSON text again

Four things to know:

  • Load a FHIR version first. (require fhir/r5/schemas) is what tells from-json what a Patient is. See FHIR versions.

  • The answer is a result, not an exception. from-json returns (ok node) or (err error), and the error carries the address of the rule in the specification:

    (from-json (hash-set js 'favouriteColour "blue"))
    ; (err (unknown-field 'Patient "https://hl7.org/fhir/R5/patient.html#Patient" 'favouriteColour))

  • Strict or lenient. By default an element FHIR does not define is an error. With #:lenient? #t it is skipped, and so is a value that does not parse, so that data from another FHIR version still loads. lenient-drops then tells you what was left out: birthDate ("25/12/1974"), favouriteColour ("blue").

  • Numbers keep their digits. In clinical data 1.50 and 1.5 are not the same statement: the first claims more precision. read-fhir-json remembers each number as it was written, and node->json-string writes it back that way. node->jsexpr gives plain Racket numbers for when you want to compute.

To print JSON the way FHIR documents are written, with resourceType first and each element in the order the specification lists it, use write-fhir-json:

(require fhir/serialize/fhir-json)
(write-fhir-json (node->jsexpr p) #:indent 2)

{

  "resourceType": "Patient",

  "id": "example",

  "active": true,

  "name": [

    {

      "use": "official",

      …

7 FHIR versions🔗

FHIR has versions, and a resource of one is not always valid in another. The types of each version are a module you load; the family calls the set of them a tower.

version

  

load it with

  

what you get

R4 (4.0.1)

  

(require fhir/r4/schemas)

  

reading, writing, navigation, validation

R5 (5.0.0)

  

(require fhir/r5/schemas)

  

the same

R6 (6.0.0-ballot4)

  

(require fhir/r6/types)

  

the same, and the forms of #lang fhir/r6

Load one version in a program. The types are known by name (Patient, Observation), so a second version loaded into the same process would replace the first one’s.

Each version also brings its operation definitions as data (fhir/r4/operations, fhir/r5/operations, fhir/r6/operations) and the code lists FHIR fixes (terminology), which is how (gender "florp") is caught.

All of this is generated from the specification HL7 publishes, and never edited by hand: raco fhir regen writes it and raco fhir check confirms that what is on disk is what a fresh generation gives.

8 Operations as functions🔗

FHIR names its services with a dollar sign: $validate checks a resource, $expand lists the codes of a value set, $transform runs a map. On a server you call one over HTTP. Here each is an ordinary function, and no server is involved.

(require json fhir/r5/schemas fhir/operation
         (only-in fhir/conformance/operations ensure-valid)      ; fhir-validation: $validate
         (only-in fhir/terminology/operations))                  ; fhir-tx: $expand, $validate-code …
(define patient (call-with-input-file "patient.json" read-json))
 
(apply-operation "$validate" patient)
; an OperationOutcome saying "All OK (FHIR R5 (5.0.0))"
 
(apply-operation "ValueSet/$expand" #:url "http://hl7.org/fhir/ValueSet/administrative-gender")
; a ValueSet whose expansion holds male, female, other, unknown
 
(define validate (operation "$validate"))       ; look it up once
(validate patient)                              ; then call it like any function
(~> patient (ensure-valid) (validate))          ; pass a value through several

How it works:

  • You name the operation, by its code ("$validate"), by type and code when two operations share a code ("ValueSet/$validate-code"), or by the url of its definition. An ambiguous name is refused with the names to use instead.

  • The first argument is the resource it applies to; the operation’s other inputs are keywords, named as FHIR names them (#:url, #:profile). A misspelt one is an error that lists the right ones: $validate has no input parameter 'profle' (it takes: resource, mode, profile, usageContext).

  • The answer is FHIR JSON: the resource the operation returns, or a Parameters resource holding its outputs.

  • A failure raises exn:fail:operation, which carries an OperationOutcome, FHIR’s own resource for reporting problems. apply-operation/outcome returns that outcome instead of raising.

  • The package that does the work provides the operation. Requiring its module is what makes the name known; without it you get no operation $validate is registered.

$validate answers with a report whether or not the resource is valid. ensure-valid is the form for a program: it returns the resource when it is valid and raises when it is not, with every problem in the message.

invalid Patient (FHIR R5 (5.0.0)):

  Patient.gender code `florp` not in required value set http://hl7.org/fhir/ValueSet/administrative-gender; it holds female, male, other, unknown

A value set of a profile’s own, or of a guide, is checked too when its package is in current-sd-packages.

The same functions are what fhir-server answers with over HTTP, and you can add your own: make-operation and register-operation!, in the reference.

9 How definitions and data are found🔗

A profile, a value set, a map: each has a web address, its canonical url, and everything that refers to it uses that address. Nothing is fetched from the address; it is a name. When an operation needs the definition behind one, it looks in three places, in this order.

  • The data you gave it: current-data-source. This is where an operation finds resources to work on, such as the patients a measure counts. It can be a list in memory, a folder of JSON files, or a FHIR server.

    (require fhir/data-source)
    (parameterize ([current-data-source (directory->data-source "data/")])
      …)

  • What your program defined: the registry (fhir/registry). A file written in one of the family’s languages registers what it defines when your program requires it: an FSH file its profiles and value sets, a map file its map, a CQL file its library. So requiring the file is enough for its definitions to be found by address. You can register resources you built yourself:

    (require fhir/registry)
    (register-resources! (list profile) #:source 'my-program)
    (ensure-valid patient #:profile "http://example.org/StructureDefinition/named-patient")

    Two sources that define the same address differently are an error naming both.

  • The published packages: current-sd-packages. FHIR itself and each Implementation Guide are published as a package, a .tgz file. By default this is the R5 specification. To validate against a published guide, name its package, then the FHIR version it is built on:

    (require fhir/r4/schemas fhir/sd/sd-index fhir/spec-package)
    (parameterize ([current-sd-packages (list (spec-package-path "hl7.fhir.us.core-6.1.0.tgz")
                                              (spec-package-path "hl7.fhir.r4.core.tgz"))])
      (ensure-valid patient #:profile "http://hl7.org/fhir/us/core/StructureDefinition/us-core-patient"))
    ; invalid Patient against …/us-core-patient (FHIR R4 (4.0.1)):
    ;  Patient.identifier minimum required = 1, but found 0

    spec-package-path finds a package by file name in the fhir-spec package, in the directories of current-package-directories, and in those the environment variable FHIR_PACKAGE_PATH names.

10 Language files as modules🔗

Each of the family’s languages is also a Racket language. Put the right first line on a file (#lang fsh, #lang fml, #lang cql, #lang vcl) and a program can require it like any module. The file is checked when the program is built, so a mistake in the map or the logic stops the build at its line.

The quickest way to see this is the template:

$ raco fhir new pipeline my-pipeline

my-pipeline: the pipeline template (fsh/, fsh-invalid/, qr2patient.map, Intake.cql, main.rkt, qr.json, tests.rkt)

next: cd my-pipeline && raco test tests.rkt   (then: racket main.rkt qr.json)

$ cd my-pipeline

$ racket main.rkt qr.json

{

  "resourceType": "Patient",

  "name": [

    {

      "text": "Ana Rivera"

    }

  ],

  "gender": "female",

It is a small program in three languages. An answered intake form (qr.json) is turned into a Patient by a map (qr2patient.map), the Patient is held to a profile (fsh/intake.fsh), and a CQL library (Intake.cql) answers a question about it. main.rkt requires the three files and calls what they provide. raco test tests.rkt checks the whole thing. The template needs the fhir-examples package, where it lives.

11 Reporting problems🔗

Every language in the family reports a problem as the same value, a diagnostic: which language, at what stage, how serious, the message, and the place. One value can then be shown three ways.

(require fhir/diagnostic)
(define d (diagnostic 'fsh 'compile 'error "`nmae` is not an element of Patient"
                      (loc "profiles.fsh" 4 3 40 4)))
(diagnostic->string d #:text source-text)

profiles.fsh:4:3: fsh compile error: `nmae` is not an element of Patient

 4 | * nmae 1..1

   |   ^^^^

diagnostic->jsexpr gives the same as JSON data (lang, phase, severity, message, source, line, column), and diagnostics->operation-outcome gives a FHIR OperationOutcome with the line and column in FHIR’s standard extensions. These are what the tools print for --format json and --format outcome: the text form goes to the error stream, the other two to standard output.

Lines and columns count from 1, as editors show them. A language that raises its problems raises exn:fail:diagnostic, which Racket prints as the message alone, with no stack trace.

12 In an editor, and for an AI agent🔗

  • In an editor. The language server, fhir-lsp, shows the same diagnostics as you type. What a language offers an editor is a contract defined here (fhir/lang/support), which each language package fulfils.

  • For an agent. fhir-mcp gives an agent a folder to work in, with tools to write, check, run and store. What a language offers there is a second contract defined here (fhir/lang/workspace). The guides raco fhir guide prints are the ones the agent reads; in the repository, .claude/skills/ holds the same workflows for an agent using the command line.

13 Limits🔗

  • Forms are for R6 only. R4 and R5 can be read, written, navigated and validated; there is no #lang fhir/r4 or fhir/r5 to write them as forms.

  • One FHIR version per program. Types are registered by name, so two versions loaded together would replace each other’s.

  • JSON only. FHIR’s XML form is not read or written, here or anywhere in the family.

  • A mistake in a .fhir6 file is named, not located. The message says which field and which value are wrong; it does not give the line.

  • Fixed code lists. A code is checked as the file builds only where FHIR requires a list whose codes the specification itself spells out. A list defined by a rule, or one that draws on another list, is not checked at that stage.

  • #lang fhir/sd narrows how many values a field has. It does not write a StructureDefinition resource; FHIR Shorthand does.

  • Snapshots. Generating a snapshot merges the profile’s changes over its base, places named slices and expands the datatypes the profile reaches into. It does not handle a slice of a slice, work out a discriminator that is not stated, expand the slices of a choice element, or follow a contentReference. raco fhir snapshot reads the base from R5.

  • raco fhir roundtrip reads with the R6 types only.

14 Words used here🔗

  • Resource: one FHIR document, such as a Patient or an Observation, written as JSON.

  • Element, field: one named part of a resource (gender, birthDate).

  • Datatype: a structure used inside resources, such as HumanName or Quantity. A primitive is a single value with a fixed format: a date, a code, a decimal.

  • Choice element: an element whose value may be one of several types, written with the type in its name: deceasedBoolean, valueQuantity. The specification writes the family as deceased[x].

  • Form: a resource written in Racket’s parenthesised notation, checked as it is built.

  • Typed node: a resource as this package holds it in memory, knowing its type.

  • Tower: the generated types of one FHIR version.

  • Profile: rules a resource must follow in some setting, on top of FHIR’s own. It is itself a resource, a StructureDefinition. Its differential states only what it changes; its snapshot spells out every element after the changes.

  • Canonical url: the web address that names a definition. It is a name; nothing needs to be served there.

  • Package, Implementation Guide (IG): a published set of profiles, value sets and examples for one purpose, distributed as a .tgz file. FHIR’s own definitions come as a package too, the core package.

  • Value set: a named set of codes. A required binding is FHIR’s rule that an element’s code must come from one.

  • Operation: a named service FHIR defines, written with a dollar sign. Its OperationDefinition is the resource that states its inputs and outputs.

  • OperationOutcome: FHIR’s resource for reporting problems. Parameters: its resource for passing named values in and out of an operation. Bundle: a resource that holds other resources.

  • Diagnostic: one problem, with its place, as the family’s tools report it.

  • Module, #lang: a Racket file other files can require; the first line of a file names the language it is written in.

15 How it is tested🔗

Against what HL7 publishes, not only its own examples:

  • Every resource in the R5 and R4 core packages is read into the typed model and written back unchanged: 2968 and 4581 resources, and HL7’s 77 and 72 test examples. raco fhir roundtrip-tck runs it.

  • Every example two published guides ship (US Core 9.0.0 and the International Patient Summary 2.0.1) reads and writes back: 274 of 274.

  • Generated snapshots are compared, element by element, with the ones HL7’s test cases expect: 80 of 80 paths, 476 of 478 cardinalities, 235 of 236 types.

  • The generated types are regenerated and compared byte for byte with what is committed (raco fhir check).

The repository’s TESTING.md has the whole table for this repository’s packages, and names the cases that differ.

fhir/operation🔗

 (require fhir/operation) package: fhir

A FHIR operation is an OperationDefinition plus an implementation, with nothing about HTTP: a procedure whose keyword arguments are the definition’s parameters. Applying is (op subject #:name value ...): the subject is the resource the operation applies to, a Parameters resource may carry inputs, a list gives several values; strings are converted for integer, decimal and boolean parameters; an unknown keyword is an error listing the parameters. The result is the return resource, or a Parameters of the outputs. The packages register their operations when loaded: $validate and ensure-valid (fhir-validation), $expand, $validate-code, $lookup, $translate (fhir-tx), $transform (fml), $evaluate-measure (cql), $sql-run (sql-on-fhir), $snapshot (here).

(apply-operation "StructureMap/$transform" qr #:srcMap fml)
(define transform (operation "StructureMap/$transform"))
(~> qr (transform #:srcMap fml) (ensure-valid) ($snapshot))

fhir/registry🔗

 (require fhir/registry) package: fhir

The module system as the FHIR registry. A #lang fsh module registers its profiles, value sets and code systems when it is instantiated, a #lang vcl module its value set, a #lang fml module its StructureMap, a #lang cql module its Library; every resolver in the family looks here between the current data source and the packages (profiles for #:profile and meta.profile, a map’s uses, the terminology resolver, $transform #:source), so requiring a module is enough for what it defines to be found by canonical, with no data source to set up. fhir/parallel🔗

 (require fhir/parallel) package: fhir

procedure

(parallel-map fn    
  items    
  [#:workers workers    
  #:setup setup]) → list?
  fn : (list/c module-path? symbol?)
  items : list?
  workers : exact-positive-integer? = (default-workers)
  setup : (or/c module-path? #f) = #f
Maps the function fn names (a module path and an export) over items on every core and answers the results in order. The workers are racket processes of their own (threads share one core, and places share one heap, whose collections stop every place), so the function is named, not passed: each worker instantiates setup (a type tower, say) and then the function’s module. Items and results are written and read as S-expressions, so they must be readable data; the sharing wins when what crosses is small next to the work — hand a worker a path or a shard number rather than the data. Items are dealt one at a time as workers finish. With one worker, or in a standalone build of the tools (where there is no racket to start workers on), the function runs in-process.

procedure

(default-workers) → exact-positive-integer?

One per core, or FHIR_WORKERS from the environment (1 keeps everything in-process).
