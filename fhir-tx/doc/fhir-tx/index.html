fhir-tx: a FHIR terminology service🔗ℹ

A terminology server as a value: $expand, $validate-code, $lookup, $subsumes, $find-matches, $translate and $closure over the CodeSystems, ValueSets and ConceptMaps in FHIR NPM packages or in resources you hold. The same service is a set of fhir/operation values, the %terminologies handle FHIRPath takes, what the validator checks bindings with, what fhir-server serves over HTTP, and what expands VCL’s implicit value set urls. The official hl7.fhir.uv.tx-ecosystem suite stands at 473 of 553, with what rests on external code systems skipped. Part of the fhir family.

1 Quick start🔗ℹ

1. Install. The packages are not on the Racket package server yet; clone the repositories side by side and install from source:

raco pkg install --link --auto fhir/fhir fhir/fhir-spec fhirpath vcl fhir/fhir-tx

2. Ask it something. Over the R5 core by default, or any package with --package:

$ raco fhir-tx expand http://hl7.org/fhir/ValueSet/administrative-gender

{"resourceType": "ValueSet", ..., "expansion": {"contains": [{"system": "http://hl7.org/fhir/administrative-gender", "code": "male", "display": "Male"}, ...]}}

$ raco fhir-tx validate-code http://hl7.org/fhir/ValueSet/administrative-gender http://hl7.org/fhir/administrative-gender female

{"resourceType": "Parameters", "parameter": [{"name": "result", "valueBoolean": true}, ...]}

$ raco fhir-tx expand http://hl7.org/fhir/us/core/ValueSet/us-core-condition-code --package hl7.fhir.us.core-6.1.0.tgz --filter diab

3. Serve it. raco fhir-tx serve –package hl7.fhir.us.core-6.1.0.tgz –port 8080 puts every operation over HTTP; GET /metadata is the CapabilityStatement, GET /metadata?mode=terminology the TerminologyCapabilities.

2 Using it🔗ℹ

2.1 Command line🔗ℹ

raco fhir-tx expand <ValueSet url> [–filter t] [–count n] [–offset n]

  

the expansion

raco fhir-tx validate-code <ValueSet url> <system> <code> [–display t]

  

is the code in the set

raco fhir-tx lookup <system> <code>

  

a concept's details

raco fhir-tx translate <ConceptMap url> <code> [–system s]

  

a code through a map

raco fhir-tx subsumes <system> <codeA> <codeB>

  

the subsumption relation

raco fhir-tx serve [–port n]

  

every operation over HTTP

raco fhir-tx tck [-v]

  

the tx-ecosystem suite, floor-ratcheted

--package names a .tgz or a file in fhir-spec, repeatable, searched in order; with none, the R5 core. The answer is the operation’s FHIR JSON. Exit codes: 0, 1 when the operation fails or the suite regresses, 2 on usage.

2.2 As operations🔗ℹ

(require fhir/terminology/operations)
($expand #:url "http://hl7.org/fhir/ValueSet/administrative-gender")
($expand #:valueSet vs #:filter "fem")                       ; a ValueSet you hold
($validate-code #:url "http://hl7.org/fhir/ValueSet/administrative-gender"
                #:system "http://hl7.org/fhir/administrative-gender" #:code "female")
($lookup #:system "http://loinc.org" #:code "85354-9")
($subsumes #:system "http://snomed.info/sct" #:codeA "73211009" #:codeB "44054006")

The packages searched are current-sd-packages; resources in current-data-source come first. An implicit VCL url (http://fhir.org/VCL?v1=…) expands too.

2.3 From Racket🔗ℹ

A resolver is (url [version]) -> resource | #f; the JSON-level functions take one and answer FHIR JSON with no tower loaded. make-terminology/resolver wraps one as the tx-service handle the validator and FHIRPath’s %terminologies take.

(require fhir/terminology/service)
(define r (packages->resolver (list "hl7.fhir.us.core-6.1.0.tgz" "hl7.fhir.r4.core.tgz")))
(expand/json r "http://hl7.org/fhir/us/core/ValueSet/us-core-condition-code" #f (hash "filter" "diab"))
(validate-code/json r "http://hl7.org/fhir/ValueSet/administrative-gender" "female"
                    "http://hl7.org/fhir/administrative-gender")
(define tx (make-terminology/resolver r))
(eval-fhirpath ast root #:externals (hash "terminologies" (list tx)))   ; fhirpath

3 How terminology is handled🔗ℹ

Codes are checked at three times by three mechanisms:

  • When a resource form compiles. Code generation expands every required binding whose ValueSet enumerates its codes or includes a whole CodeSystem from the same package (202 value sets in R6), and the fhir/r6 forms reject a literal code outside its set. Filters, imports and excludes fail open.

  • When a resource is validated. The validator checks required bindings through a tx-service when given one, else against the same offline sets. Only $validate builds a service; raco fhir-validate, the generated servers and raco fsh check pass none.

  • At run time, this service: over packages or resources, indexed lazily per package, as operations, as FHIRPath’s expand(), validateVS() and translate(), over HTTP, and for VCL’s implicit urls.

CQL takes value set expansions as data and does not call the service; FSH records a binding’s strength and url and validates no codes; FML’s translate asks it for ConceptMaps the map does not embed.

4 Limits🔗ℹ

  • What the terminology service does not do. CodeSystem supplements apply only when named by useSupplement; nothing discovers them. $closure tables live in the process. $find-matches matches properties exactly or by substring, with no compositional grammar. $expand does not take includeDefinition, excludeNotForUI or limit, and emits no abstract or inactive flags; displayLanguage matches a tag exactly. $translate is forward only, by source code and system, with no target, dependsOn or unmapped handling and no ConceptMap version. Hierarchy comes from nested concepts, not from parent or subsumedBy properties. Version resolution picks the highest version by string order. Anything resting on a code system the service cannot see (SNOMED CT, LOINC, RxNorm) is undecidable and reported as unknown, never as invalid; the tx-ecosystem suite stands at 473/553 with those skipped.

  • FHIRPath’s %terminologies offers expand() (with a Parameters argument), validateVS() and translate() (a code, a Coding or a CodeableConcept, and a system); the handle has no lookup(), subsumes() or validateCS().

5 Reference🔗ℹ

fhir/terminology/service🔗ℹ

 (require fhir/terminology/service) package: fhir-tx

A terminology server as a value. Expansion follows compose (includes, excludes, filters over the code system’s concepts and properties, nested value sets, version pins including 1.x.x patterns, implicit VCL urls) with the expansion parameters (offset, count, activeOnly, filter, displayLanguage, includeDesignations, property). Validation takes a code, a Coding or a CodeableConcept, checks displays against designations, and honours system and value set versions. What rests on a code system the service does not have (SNOMED, LOINC) is undecidable; the hl7.fhir.uv.tx-ecosystem suite is at 473/553 with those skipped.

The four as fhir/operation values on the core OperationDefinitions, registered when the module loads. A ValueSet is the subject, #:valueSet, or named by #:url; the inputs are the definitions’ parameters (($translate cm #:sourceCode "a" #:system url)). Resources are looked up in the inputs, then current-data-source, then current-sd-packages.
