9.3

fhir-tx: codes, code systems and value sets🔗

Health records are full of codes. A diagnosis, a lab test, a patient’s gender, the status of an order: each is written as a short code from an agreed list rather than as free text, so that two systems mean the same thing by it. Working with such data keeps raising the same few questions. Which codes are allowed here? Is this code one of them? What does this code mean? What is the matching code in that other list?

Answering them is the job of a terminology service, and FHIR defines what one must answer. This package is a terminology service. It reads the code lists that FHIR and the published Implementation Guides ship, and answers those questions from the command line (raco fhir-tx), over HTTP, or as functions in a program.

Part of the fhir family of FHIR languages and tools.

1 What you can do with it🔗

  • List the codes in a value set: Which codes are in this value set? ($expand).

  • Ask whether a code is in a value set: Is this code in it? ($validate-code).

  • Ask what a code means: What does this code mean? ($lookup).

  • Find the matching code in another system: What is this code in another system? ($translate).

  • Ask whether one code is a kind of another: Is this code a kind of that one? ($subsumes).

  • Serve all of this over HTTP, as a FHIR terminology server: Serving it over HTTP.

  • Use it from a program, from FHIRPath, or to let the validator check codes: From a program.

2 A first example🔗

1. Install the tools as the family’s front page describes. The command is then raco fhir-tx (or fhir-tx, if you built the standalone tools).

2. Ask which codes a value set holds. FHIR says a patient’s gender must be one of a small set of codes. That set has a name, which is a web address: http://hl7.org/fhir/ValueSet/administrative-gender. Ask for its members:

$ raco fhir-tx expand http://hl7.org/fhir/ValueSet/administrative-gender

{"expansion":{"contains":[{"code":"male","display":"Male","system":"http://hl7.org/fhir/administrative-gender","version":"5.0.0"},{"code":"female","display":"Female", …},{"code":"other","display":"Other", …},{"code":"unknown","display":"Unknown", …}],"total":4},"resourceType":"ValueSet","url":"http://hl7.org/fhir/ValueSet/administrative-gender"}

The answer is JSON, a FHIR ValueSet resource. Its expansion.contains is the list: four codes, each with the text shown to people (display) and the code system it comes from (system).

3. Ask whether a code is in it. Give the value set, the code’s system and the code:

$ raco fhir-tx validate-code http://hl7.org/fhir/ValueSet/administrative-gender http://hl7.org/fhir/administrative-gender female

{"parameter":[{"name":"result","valueBoolean":true},{"name":"code","valueCode":"female"},{"name":"system","valueUri":"http://hl7.org/fhir/administrative-gender"},{"name":"display","valueString":"Female"}],"resourceType":"Parameters"}

This answer is a FHIR Parameters resource, a list of named values. The one to read is result: true.

4. Make a mistake. Ask about femme:

$ raco fhir-tx validate-code http://hl7.org/fhir/ValueSet/administrative-gender http://hl7.org/fhir/administrative-gender femme

{"parameter":[{"name":"result","valueBoolean":false},{"name":"code","valueCode":"femme"},{"name":"system","valueUri":"http://hl7.org/fhir/administrative-gender"},{"name":"message","valueString":"Unknown code 'femme' in the CodeSystem 'http://hl7.org/fhir/administrative-gender'"}],"resourceType":"Parameters"}

result is false, and message says why. Note that the command itself succeeded: "no" is an answer, not a failure, so the exit code is 0.

3 Codes, code systems and value sets🔗

Three ideas carry everything on this page.

A code system is a list of codes with their meanings, kept by one organisation. LOINC lists laboratory tests and measurements, SNOMED CT clinical findings and procedures, ICD-10 diagnoses. FHIR has many small ones of its own, such as the four administrative genders. A code system is named by an address, like http://loinc.org or http://hl7.org/fhir/administrative-gender.

A code only means something together with its system: female in http://hl7.org/fhir/administrative-gender, 4548-4 in http://loinc.org (an HbA1c test). A code and its system written together are a coding. Each code has a display, the words shown to a person.

A value set is a selection of codes for one purpose: "the codes allowed for a patient’s gender", "the codes that mean a blood-pressure reading". It can draw from one code system or several, and it is defined in one of two ways:

  • by listing its codes one by one; or

  • by a rule over a code system: "every code in this system", "this code and everything beneath it", "the codes whose property X is Y".

The difference matters here. To turn a list into its members, the service needs only the value set. To turn a rule into its members, it needs the whole code system the rule is about (What it cannot answer offline).

One more: a concept map says which code in one system corresponds to which in another, for moving data between systems.

Code systems, value sets and concept maps are themselves FHIR resources (CodeSystem, ValueSet, ConceptMap), published inside packages: the FHIR specification is one package, each Implementation Guide another. Those packages are what the service reads (Which packages it reads).

4 The questions it answers🔗

FHIR calls each kind of question an operation and writes its name with a dollar sign. Each has a command of the same name.

4.1 Which codes are in this value set? ($expand)🔗

raco fhir-tx expand <value set> lists the members, as in the first example. Listing a value set’s members is called expanding it, and the list is its expansion.

Large value sets are read in parts. --filter keeps the members whose code or display contains a text (in any letter case); --count and --offset take a page of them. total counts every member that passed the filter, not just the page:

$ raco fhir-tx expand http://hl7.org/fhir/ValueSet/administrative-gender --filter fem

{"expansion":{"contains":[{"code":"female","display":"Female","system":"http://hl7.org/fhir/administrative-gender","version":"5.0.0"}],"total":1},"resourceType":"ValueSet","url":"http://hl7.org/fhir/ValueSet/administrative-gender"}

4.2 Is this code in it? ($validate-code)🔗

raco fhir-tx validate-code <value set> <system> <code> answers true or false in result, with the code’s display when it is found and a message when it is not.

It can check the display too. Systems often send a code with the wrong words beside it, which is a sign the wrong code was picked. --display gives the words you have:

$ raco fhir-tx validate-code http://hl7.org/fhir/ValueSet/administrative-gender http://hl7.org/fhir/administrative-gender female --display Woman

{"parameter":[{"name":"result","valueBoolean":false},{"name":"code","valueCode":"female"},{"name":"system","valueUri":"http://hl7.org/fhir/administrative-gender"},{"name":"display","valueString":"Female"},{"name":"message","valueString":"Wrong Display Name 'Woman', should be 'Female'"}],"resourceType":"Parameters"}

4.3 What does this code mean? ($lookup)🔗

raco fhir-tx lookup <system> <code> gives what the code system says about one code. Here the code is required, one of the kinds of problem a FHIR validator reports:

$ raco fhir-tx lookup http://hl7.org/fhir/issue-type required

{"parameter":[{"name":"name","valueString":"IssueType"},{"name":"version","valueString":"5.0.0"},{"name":"display","valueString":"Required element missing"},{"name":"definition","valueString":"A required element is missing."}],"resourceType":"Parameters"}

name and version are the code system’s; display and definition are the code’s. A code the system does not have is an error that says so (exit status 1), as the $lookup operation answers it.

4.4 What is this code in another system? ($translate)🔗

raco fhir-tx translate <concept map> <code> sends a code through a concept map. FHIR ships a map from its gender codes to the ones the older HL7 version 2 messages use:

$ raco fhir-tx translate http://hl7.org/fhir/ConceptMap/cm-administrative-gender-v2 female

{"parameter":[{"name":"result","valueBoolean":true},{"name":"match","part":[{"name":"relationship","valueCode":"equivalent"},{"name":"concept","valueCoding":{"code":"F","system":"http://terminology.hl7.org/CodeSystem/v2-0001"}}]}],"resourceType":"Parameters"}

Each match is a target code and how good the match is: equivalent here. A code can have several matches, or a looser one: the same map sends other to two version 2 codes, each marked source-is-broader-than-target. A code the map does not mention answers result false. --system names the source code’s system when the map has groups for several.

The operation can also be asked without naming a map: given the source system and the targetSystem, it uses every map in context between the two, and each match names the map that made it (originMap).

4.5 Is this code a kind of that one? ($subsumes)🔗

Many code systems are trees: a broad code with narrower ones beneath it. FHIR’s issue types are one: invalid has structure, required, value and invariant under it. raco fhir-tx subsumes <system> <codeA> <codeB> says how two codes stand:

$ raco fhir-tx subsumes http://hl7.org/fhir/issue-type invalid required

{"parameter":[{"name":"outcome","valueCode":"subsumes"}],"resourceType":"Parameters"}

subsumes means the first is the broader one. The other answers are subsumed-by (the first is the narrower), equivalent and not-subsumed (neither contains the other). Here a code the system does not have is an error, with exit code 1:

$ raco fhir-tx subsumes http://hl7.org/fhir/issue-type required nosuch

fhir-tx: subsumes: unknown code nosuch in http://hl7.org/fhir/issue-type

5 Which packages it reads🔗

The service knows the code systems, value sets and concept maps in the packages it is given, and nothing else. With no option that is the FHIR R5 specification. --package names another package, and can be repeated; the packages are searched in the order given.

An Implementation Guide’s value sets usually draw on code systems from the FHIR version the guide is written for, so name both: the guide, then its core package. US Core 6.1.0 is written for R4:

$ raco fhir-tx expand http://hl7.org/fhir/us/core/ValueSet/us-core-screening-assessment-observation-category \

    --package hl7.fhir.us.core-6.1.0.tgz --package hl7.fhir.r4.core.tgz

{"expansion":{"contains":[{"code":"sdoh","display":"SDOH","system":"http://hl7.org/fhir/us/core/CodeSystem/us-core-category","version":"6.1.0"},{"code":"functional-status","display":"Functional Status", …},{"code":"disability-status","display":"Disability Status", …},{"code":"cognitive-status","display":"Cognitive Status", …}],"total":4},"resourceType":"ValueSet","url":"http://hl7.org/fhir/us/core/ValueSet/us-core-screening-assessment-observation-category"}

A package is named by the path of its .tgz file, or by the file name of one that comes with the tools (with or without .tgz). Those are the core specification (hl7.fhir.r4.core, hl7.fhir.r5.core, hl7.fhir.r6.core), US Core (hl7.fhir.us.core-6.1.0, hl7.fhir.us.core-8.0.0, and hl7.fhir.us.core, which is 9.0.0), the International Patient Summary (hl7.fhir.uv.ips), mCODE (hl7.fhir.us.mcode-4.0.0), CQF Measures (hl7.fhir.us.cqfmeasures-5.0.0), CRMI (hl7.fhir.uv.crmi-2.0.0) and Genomics Reporting (hl7.fhir.uv.genomics-reporting-2.0.0). Other packages are downloaded from packages.fhir.org; a directory named in the environment variable FHIR_PACKAGE_PATH is searched for them by name too.

6 What it cannot answer offline🔗

The big clinical code systems are not in any FHIR package. SNOMED CT, LOINC, RxNorm, ICD-10 and CPT are large, separately licensed, and distributed by their owners. This service does not ship them and does not call out to a server that has them. So it knows that http://loinc.org is a code system, but not what is in it. That has three consequences. The service marks each of them in its answer, so you can tell "no" from "cannot say".

A value set that lists such codes works, without displays. Membership needs only the list. US Core’s vital signs are LOINC codes written out one by one:

$ raco fhir-tx expand http://hl7.org/fhir/us/core/ValueSet/us-core-vital-signs \

    --package hl7.fhir.us.core-6.1.0.tgz --package hl7.fhir.r4.core.tgz --count 3

{"expansion":{"contains":[{"code":"59576-9","system":"http://loinc.org"},{"code":"8289-1","system":"http://loinc.org"},{"code":"77606-2","system":"http://loinc.org"}],"total":19},"resourceType":"ValueSet","url":"http://hl7.org/fhir/us/core/ValueSet/us-core-vital-signs"}

The codes are there and validate-code answers correctly for them. There is no display, because the words live in LOINC.

A value set defined by a rule over such a system comes back short or empty. US Core’s condition codes are one listed SNOMED CT code plus three rules of the form "this SNOMED CT code and everything beneath it". (It also takes all of ICD-10-CM and ICD-9-CM, which are not shipped either.) The expansion holds the one listed code, and says that this is not every code:

$ raco fhir-tx expand http://hl7.org/fhir/us/core/ValueSet/us-core-condition-code \

    --package hl7.fhir.us.core-6.1.0.tgz --package hl7.fhir.r4.core.tgz

fhir-tx: not every code is listed: the value set selects from http://snomed.info/sct,

  http://hl7.org/fhir/sid/icd-10-cm, http://hl7.org/fhir/sid/icd-9-cm by rule, and that content

  is not in the packages (the expansion is marked valueset-unclosed)

{"expansion":{"contains":[{"code":"160245001","system":"http://snomed.info/sct"}],

  "extension":[{"url":"http://hl7.org/fhir/StructureDefinition/valueset-unclosed","valueBoolean":true}],

  "total":1},"resourceType":"ValueSet","url":"http://hl7.org/fhir/us/core/ValueSet/us-core-condition-code"}

(Both the note and the JSON are one line each; they are wrapped here.) The note goes to standard error. The mark in the answer itself is FHIR’s own valueset-unclosed extension on the expansion, which a program can test for.

For the same reason, a SNOMED CT code that the rules do include (type 2 diabetes, 44054006, for one) cannot be confirmed. validate-code answers result false, as the operation must answer true or false, and says why in two more parameters:

$ raco fhir-tx validate-code http://hl7.org/fhir/us/core/ValueSet/us-core-condition-code \

    http://snomed.info/sct 44054006 --package hl7.fhir.us.core-6.1.0.tgz --package hl7.fhir.r4.core.tgz

{"parameter":[{"name":"result","valueBoolean":false},{"name":"code","valueCode":"44054006"},

  {"name":"system","valueUri":"http://snomed.info/sct"},

  {"name":"message","valueString":"Whether '44054006' is in the value set cannot be decided here:

     the value set selects from http://snomed.info/sct by rule, and that code system's content is

     not in the packages"},

  {"name":"x-caused-by-unknown-system","valueCanonical":"http://snomed.info/sct"}],

 "resourceType":"Parameters"}

x-caused-by-unknown-system is the parameter the reference terminology server uses for the same situation: read a false that carries it as "cannot say", not as "not allowed". A code of a system that is at hand gets a plain true or false.

Questions about the system itself are refused. lookup and subsumes on a system whose content is not there say so and exit with 1:

$ raco fhir-tx lookup http://loinc.org 4548-4

fhir-tx: no CodeSystem http://loinc.org in the R5 core package (name others with --package)

The family’s validator reads these marks: when it checks a resource’s codes through this service and the value set rests on a system that is not there, it reports nothing rather than call the code invalid (fhir-validation).

A misspelt address is an error too, on the command line as over HTTP, not an empty answer:

$ raco fhir-tx expand http://example.org/ValueSet/nope

fhir-tx: no ValueSet http://example.org/ValueSet/nope in the R5 core package (name others with --package)

7 Serving it over HTTP🔗

Other software asks a terminology service its questions over the web, in the way FHIR lays down. One command starts such a server:

$ raco fhir-tx serve --port 8080

terminology server on http://localhost:8080  (GET /metadata, /metadata?mode=terminology; Ctrl-C, or kill 8987, to stop)

It serves the R5 specification’s terminology unless you give --packages, as above. The port is 8080 unless you say otherwise. Ask it something from another terminal, here with curl. The address has the kind of resource, then the operation; the inputs follow the question mark:

$ curl 'http://localhost:8080/ValueSet/$expand?url=http://hl7.org/fhir/ValueSet/administrative-gender&filter=fem'

{"resourceType":"ValueSet","url":"http://hl7.org/fhir/ValueSet/administrative-gender","expansion":{"total":1,"contains":[{"system":"http://hl7.org/fhir/administrative-gender","version":"5.0.0","code":"female","display":"Female"}]}}

 

$ curl 'http://localhost:8080/ValueSet/$validate-code?url=http://hl7.org/fhir/ValueSet/administrative-gender&code=female'

{"resourceType":"Parameters","parameter":[{"name":"result","valueBoolean":true},{"name":"code","valueCode":"female"},{"name":"display","valueString":"Female"}]}

 

$ curl 'http://localhost:8080/CodeSystem/$lookup?system=http://hl7.org/fhir/issue-type&code=required'

{"resourceType":"Parameters","parameter":[{"name":"name","valueString":"IssueType"},{"name":"version","valueString":"5.0.0"},{"name":"display","valueString":"Required element missing"},{"name":"definition","valueString":"A required element is missing."}]}

 

$ curl 'http://localhost:8080/ConceptMap/$translate?url=http://hl7.org/fhir/ConceptMap/cm-administrative-gender-v2&sourceCode=female'

{"resourceType":"Parameters","parameter":[{"name":"result","valueBoolean":true},{"name":"match","part":[{"name":"relationship","valueCode":"equivalent"},{"name":"concept","valueCoding":{"system":"http://terminology.hl7.org/CodeSystem/v2-0001","code":"F"}}]}]}

The whole list of what is served:

address

  

question

/ValueSet/$expand

  

which codes are in the value set

/ValueSet/$validate-code

  

is the code in the value set

/CodeSystem/$validate-code

  

is the code in the code system

/CodeSystem/$lookup

  

what the code means

/CodeSystem/$subsumes

  

how two codes stand in the hierarchy

/CodeSystem/$find-matches

  

the codes with given properties

/ConceptMap/$translate

  

the code in another system

/$closure

  

a running table of how the codes a client has sent relate

/metadata

  

the server's CapabilityStatement: what it supports

/metadata?mode=terminology

  

its TerminologyCapabilities: the code systems it holds

/OperationDefinition

  

the formal definition of each operation

Inputs can also be sent as a Parameters resource in a POST, which is how a Coding or a whole value set is passed:

$ curl -X POST -H 'Content-Type: application/fhir+json' 'http://localhost:8080/ValueSet/$validate-code' -d '

{"resourceType": "Parameters", "parameter": [

  {"name": "url", "valueUri": "http://hl7.org/fhir/ValueSet/administrative-gender"},

  {"name": "coding", "valueCoding": {"system": "http://hl7.org/fhir/administrative-gender", "code": "female"}}]}'

{"resourceType":"Parameters","parameter":[{"name":"result","valueBoolean":true},{"name":"code","valueCode":"female"},{"name":"system","valueUri":"http://hl7.org/fhir/administrative-gender"},{"name":"display","valueString":"Female"}]}

A question that cannot be answered gets an OperationOutcome, FHIR’s report of a problem, and an HTTP error status. An unknown value set is 404:

$ curl 'http://localhost:8080/ValueSet/$expand?url=http://example.org/nope'

{"resourceType":"OperationOutcome","issue":[{"severity":"error","code":"not-found","diagnostics":"$expand: ValueSet http://example.org/nope is not in the data source or the packages"}]}

--url sets the address the server gives as its own in its CapabilityStatement, for when it is reached through another name than localhost. Serving needs the fhir-server package, which is installed with the rest. A server generated from an Implementation Guide by raco fhir-server serve-ig serves $expand as well when the guide asks for it, over the value sets it stores and the guide’s packages.

The line the server prints when it is ready ends with its process id (Ctrl-C, or kill 8987, to stop), and is written at once, to a terminal or to a file: a script that started the server in the background can wait for that line, then stop the server by the id.

8 From a program🔗

8.1 As operations🔗

In a Racket program each operation is a function, and its inputs are keyword arguments with the names FHIR gives them. The answers are the same FHIR JSON as on the command line, as hash tables.

(require fhir/terminology/operations)
(define gender "http://hl7.org/fhir/ValueSet/administrative-gender")
 
($expand #:url gender)                                       ; the ValueSet with its expansion
($expand #:url gender #:filter "fem")
($validate-code #:url gender #:system "http://hl7.org/fhir/administrative-gender" #:code "female")
($lookup #:system "http://hl7.org/fhir/issue-type" #:code "required")
($subsumes #:system "http://hl7.org/fhir/issue-type" #:codeA "invalid" #:codeB "required")
($translate #:url "http://hl7.org/fhir/ConceptMap/cm-administrative-gender-v2" #:sourceCode "female")

A value set does not have to be published anywhere. Give one you hold, as the first argument or as #:valueSet:

(define binary
  (hasheq 'resourceType "ValueSet" 'url "http://example.org/ValueSet/binary"
          'compose (hasheq 'include
                           (list (hasheq 'system "http://hl7.org/fhir/administrative-gender"
                                         'concept (list (hasheq 'code "female") (hasheq 'code "male")))))))
($expand binary)                                             ; female, male
($validate-code binary #:system "http://hl7.org/fhir/administrative-gender" #:code "other")
; result false: The code 'other' is not in the value set

Where definitions are looked for. A value set, code system or concept map named by its address is looked for, in this order: in the inputs of the call; among the resources of current-data-source (data you hold: a folder, a Bundle, a server’s store); among the definitions that Racket modules in the family’s languages have registered (a #lang vcl value set, a #lang fsh code system, once the file is required); in the packages of current-sd-packages, which with nothing set is the R5 core.

(require fhir/sd/sd-index fhir/spec-package)
(parameterize ([current-sd-packages (list (spec-package-path "hl7.fhir.us.core-6.1.0.tgz")
                                          (spec-package-path "hl7.fhir.r4.core.tgz"))])
  ($expand #:url "http://hl7.org/fhir/us/core/ValueSet/us-core-screening-assessment-observation-category"))

A value set that is found nowhere raises exn:fail:operation: $expand: ValueSet http://example.org/nope is not in the data source or the packages.

A value set written in the address. The ValueSet Compose Language (VCL) writes a value set as one short expression, and FHIR lets that expression stand in an address. The service expands such an address with no value set stored anywhere:

($expand #:url "http://fhir.org/VCL?v1=(http://hl7.org/fhir/administrative-gender)(male;female)")
; male, female

8.2 Without the operations: resolvers🔗

Under the operations are plain functions over a resolver: a function from an address (and optionally a version) to the resource it names, or #f. You make one from packages or from resources, and pass it to the function for each question. This is the level to use when you do not want the operation machinery, or when you hand the service to something else.

(require fhir/terminology/service fhir/spec-package)
(define r (packages->resolver (list (spec-package-path "hl7.fhir.us.core-6.1.0.tgz")
                                    (spec-package-path "hl7.fhir.r4.core.tgz"))))
(expand/json r "http://hl7.org/fhir/us/core/ValueSet/us-core-vital-signs" #f (hash "count" 2))
(validate-code/json r "http://hl7.org/fhir/ValueSet/administrative-gender" "female"
                    "http://hl7.org/fhir/administrative-gender")
(lookup/json r "http://hl7.org/fhir/administrative-gender" "female")

8.3 In FHIRPath, and for the validator🔗

make-terminology/resolver wraps a resolver as the service handle two other parts of the family take. FHIRPath expressions reach it as %terminologies; here an expression asks whether a patient’s gender is in the value set:

(require fhirpath/eval fhirpath/parser/parse fhir/r4/schemas)
(define tx (make-terminology/resolver r))
; patient: a Patient read with from-json (fhir/serialize/from-json)
(eval-fhirpath
 (parse-fhirpath "%terminologies.validateVS('http://hl7.org/fhir/ValueSet/administrative-gender', gender).parameter.where(name = 'result').value")
 (list patient)
 #:externals (hash "terminologies" (list tx)))
; => true, for a patient whose gender is female

The validator takes the same handle as #:terminology, to check a resource’s codes against value sets it could not otherwise list.

9 Where codes are checked in the family🔗

Codes are checked at three moments, by three mechanisms, and it helps to know which one you are relying on.

  • When a resource is written as a program. The Racket forms for FHIR resources (fhir/r6 and the others) refuse a literal code outside its set when the file compiles. The sets were worked out when the forms were generated: every required binding whose value set lists its codes or takes a whole code system from the same package (202 value sets in R6). Value sets with rules, imports or exclusions are left unchecked there.

  • When a resource is validated. The validator checks required bindings through this service when it is given one, else against those same built-in sets. Only the $validate operation builds a service for itself; raco fhir-validate, the generated servers and raco fsh check use the built-in sets.

  • When you ask, by this service: over packages or resources, as commands, as operations, as FHIRPath’s expand(), validateVS() and translate(), over HTTP, and for VCL addresses.

The languages use it differently. CQL takes value set expansions as data and does not call the service. FHIR Shorthand records which value set an element is bound to and validates no codes itself. The mapping language’s translate asks the service for a concept map the map file does not contain.

11 Limits🔗

  • External code systems. SNOMED CT, LOINC, RxNorm and the like are not shipped and not fetched. What follows from that, and how the answers are marked, is in What it cannot answer offline.

  • $expand takes filter, count, offset, activeOnly, excludeNested, displayLanguage, includeDesignations, designation, includeDefinition, property, useSupplement and the version parameters. It does not take excludeNotForUI, exclude-system or limit, and does not flag members as abstract or inactive. A language tag in displayLanguage also serves its regional forms (en for en-AU and the reverse).

  • Refusals. Through the operations and the command line, a request that cannot be answered as asked is an OperationOutcome: a value set or supplement nothing defines, a code system version a definition pins and nothing holds, a version check-system-version forbids, a filter with no value, a value set that includes itself, a display language that is no tag. Called from a program (expand/json and the others) with current-terminology-strict? off, the default, the same request is answered with what can be said without it (no codes, the supplement left out): that is how the validator and FHIRPath ask, since they must not fail on what they cannot decide.

  • Regular expressions in a filter are matched with a time limit (0.2 s a code): a pattern that backtracks without end takes nothing, as the reference server does.

  • $translate goes forward only, from a source code and system. It does not translate towards a given target, and ignores a map’s dependsOn and unmapped parts and its version.

  • Hierarchy is read from codes nested inside one another in the CodeSystem resource, not from parent or subsumedBy properties.

  • Versions. When several versions of a code system or value set are at hand and none is asked for, the highest is taken, comparing the version texts as strings.

  • Supplements to a code system apply when a request names them with useSupplement or the value set names them (the valueset-supplement extension); one that is not here is a refusal. None is found by itself.

  • UCUM has no list of codes: a value set that takes it by rule holds every valid unit, narrowed by a canonical = filter to the units that measure what that unit measures. Such a value set is validated against but not expanded.

  • $find-matches matches properties exactly or by substring; it has no grammar for composed expressions.

  • $closure tables live in the running process and are gone when it stops.

  • FHIRPath’s %terminologies offers expand() (with a Parameters argument), validateVS() and translate() (a code, a Coding or a CodeableConcept, and a system), and answers FHIR’s memberOf(), subsumes() and subsumedBy(). It has no lookup() or validateCS().

12 Words used here🔗

  • Code: a short identifier with an agreed meaning. Display: the words shown for it.

  • Code system: a list of codes and their meanings, named by an address (LOINC, SNOMED CT, FHIR’s own small lists). As a resource, a CodeSystem.

  • Coding: a code together with its system. CodeableConcept: one idea written as one or more codings and optional text.

  • Value set: a selection of codes for one purpose, listed or defined by a rule. As a resource, a ValueSet; its definition is its compose.

  • Expansion: the list of codes a value set comes to. To expand is to work it out.

  • Concept map: a table from the codes of one system to those of another (a ConceptMap).

  • Binding: the statement, in FHIR or a profile, that an element’s code comes from a value set. A required binding allows no other code.

  • Subsumes: "is broader than and includes", between two codes of a hierarchy.

  • Operation: a named service FHIR defines, written with a dollar sign ($expand).

  • Parameters: the FHIR resource that carries an operation’s named inputs or outputs. OperationOutcome: the one that reports a problem.

  • Canonical url: the web address that names a value set, code system or concept map. It is a name; nothing needs to be served there.

  • Package: the .tgz file an Implementation Guide or the FHIR specification is distributed as.

  • CapabilityStatement, TerminologyCapabilities: a server’s own description of what it supports and of the code systems it holds.

  • VCL: the ValueSet Compose Language, a one-line way to write a value set.

  • Resolver: in the programming interface, the function that finds a resource by its address.

13 How it is tested🔗

HL7 publishes a conformance suite for terminology servers, hl7.fhir.uv.tx-ecosystem (version 1.9.3 here): requests with the responses a correct server gives. raco fhir-tx tck runs it:

$ raco fhir-tx tck

terminology conformance: 601/601  (skipped 319: suites for content not here, such as SNOMED CT,

  LOINC and OMOP; candidate operations; -v says why each)

Every one of the 600 cases it attempts gives the expected response: the codes of an expansion, the verdict of a validation, the display of a lookup, and a refusal (an OperationOutcome) where one is expected. The 320 skipped are counted, not hidden, and -v gives the reason for each: 249 belong to suites written for a server that holds SNOMED CT, LOINC, OMOP, HGVS or ICD-11, or are one server’s own regression tests, and that content is not shipped; 61 ask a candidate operation that compares two value sets, and 2 a batch of validations, neither of them FHIR’s; 3 expand UCUM by rule, which no list of codes answers; 3 ask for a server’s metadata; 2 translate by code system rather than by ConceptMap (Limits). The number is a floor: the command fails if it drops. -v also lists each failing case. The repository’s TESTING.md has the other suites.
