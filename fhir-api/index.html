fhir-api: the toolkit from Python, and from any other language🔗

The toolkit is written in Racket. Most people who work with health data write Python. This page is how the two meet: a Python package, agentfhir, whose functions compile, check, run and validate FHIR and its languages, and under it a small server that any other language can speak to in the same way.

Part of the fhir family of FHIR languages and tools.

1 What you can do with it🔗

  • Ask a question of a resource in FHIRPath, and get Python values back.

  • Check that a resource is valid FHIR, or valid against a profile you wrote in a few lines of FSH.

  • Turn FHIR resources into a table (a pandas DataFrame) with a view, and join tables in SQL.

  • Run clinical logic written in CQL over patients’ data, or get its ELM.

  • Convert a resource with a map, expand a value set, write a resource back as FSH.

  • Get every problem as a value with its file, line and column, so your program can point at it.

2 A first example🔗

Install the package. It is not on the Python Package Index yet: a wheel is built by this repository’s wheels workflow, and From a source checkout says how to use a source checkout meanwhile. A wheel carries the toolkit itself, so nothing else is needed.

  pip install agentfhir-0.1.0-py3-none-<your platform>.whl

Then make a FhirContext and call it. Each line under a # is what the example prints.

  from agentfhir import FhirContext

  

  fhir = FhirContext()

  

  patient = {

      "resourceType": "Patient", "id": "ann", "gender": "female", "birthDate": "1980-02-28",

      "name": [{"family": "Lee", "given": ["Ann"]}],

  }

  

  print(fhir.fhirpath("name.given.first() + ' ' + name.family.first()", patient))

  print(fhir.validate(patient).ok)

  print(fhir.validate({"resourceType": "Patient", "gender": "florp"}).messages())

  

  # ['Ann Lee']

  # True

  # ['Patient.gender: error: code `florp` not in required value set http://hl7.org/fhir/ValueSet/administrative-gender; it holds female, male, other, unknown']

FhirContext() starts one process of the toolkit in the background and returns at once; the process is kept for every call. A call adds about a tenth of a millisecond to the work it asks for. fhirpath answers a list, because a FHIRPath expression answers a collection. validate answers an outcome: .ok is true when no issue is an error, and .messages() is one line for each issue, starting with the element it is about.

3 Projects and data🔗

Two words carry the rest of the package.

A project is the sources a call may refer to: a profile in FSH, a CQL library, a map, a value set, a view, a FHIR definition as JSON. You give it as a dictionary of file name to text (the name’s ending says the language: .fsh, .cql, .map, .vcl, .sof, .json), or as the path of a directory. What the project defines is in context for the call. Here a profile is the project, and a resource is held to it:

  profile = """

  Profile: AdultPatient

  Parent: Patient

  * birthDate 1..1

  """

  

  outcome = fhir.validate({"resourceType": "Patient", "gender": "female"}, "AdultPatient", project={"rules.fsh": profile})

  print(outcome.ok)

  print(outcome.messages())

  

  # False

  # ['Patient.birthDate: error: minimum required = 1, but found 0']

A mistake in a source is an exception, FhirError, whose diagnostics say where:

  from agentfhir import FhirError

  

  try:

      fhir.fsh("Profile: P\nParent: Patient\n* nmae 1..1\n")

  except FhirError as error:

      print(error.diagnostics[0])

  

  # input.fsh:3:3: error: profile: P: `nmae` is not an element of Patient (did you mean `name`?)

Data is the FHIR a call reads. Give resources (a list, one resource, a Bundle), or a string: the path of a directory of FHIR JSON, of a JSON file or of a SQLite FHIR store, or the base url of a FHIR server.

4 Tables🔗

A view is a SELECT whose columns are FHIRPath expressions; it turns resources of one type into rows. to_pandas() gives a DataFrame (it needs pandas installed).

  observation = {

      "resourceType": "Observation", "id": "a1", "status": "final",

      "code": {"coding": [{"system": "http://loinc.org", "code": "4548-4"}]},

      "subject": {"reference": "Patient/ann"}, "effectiveDateTime": "2025-03-01",

      "valueQuantity": {"value": 9.4, "unit": "%", "system": "http://unitsofmeasure.org", "code": "%"},

  }

  data = [patient, observation]

  

  frame = fhir.view("SELECT id, name.family.first() AS family, birthDate FROM Patient", data).to_pandas()

  print(frame.to_string())

  

  #     id family   birthDate

  # 0  ann    Lee  1980-02-28

Several views in a project are tables of their names, and sql runs a statement over them:

  views = {

      "patients.sof": "CREATE VIEW patients WITH (status = 'active') AS "

                      "SELECT getResourceKey() AS id, name.family.first() AS family FROM Patient",

      "results.sof": "CREATE VIEW results WITH (status = 'active') AS "

                     "SELECT subject.getReferenceKey(Patient) AS patient, value.ofType(Quantity).value AS value FROM Observation",

  }

  table = fhir.sql("SELECT p.family, r.value FROM results r JOIN patients p ON p.id = r.patient", project=views, data=data)

  print(table.columns, table.rows)

  

  # ['family', 'value'] [{'family': 'Lee', 'value': 9.4}]

5 Clinical logic🔗

cql runs a library over the data and answers one row for each patient, one column for each definition. translate answers the library’s ELM, the form other CQL engines run.

  library = """

  library A1c version '1.0'

  using FHIR version '4.0.1'

  include FHIRHelpers version '4.0.1'

  context Patient

  define "Latest": Last([Observation] O sort by (effective as dateTime))

  define "Above 9": (Latest.value as Quantity) > 9 '%'

  """

  

  print(fhir.cql(library, data).rows)

  print(fhir.elm(library)["library"]["identifier"])

  

  # [{'Above 9': True, 'Latest': 'Observation/a1', 'patient': 'ann'}]

  # {'id': 'A1c', 'version': '1.0'}

6 Writing data🔗

write puts resources into a store, a SQLite file made the first time. Each resource is validated first, and one error means nothing is written. What is written leaves a trail in the store: who wrote which version, when and why.

  gender = "http://hl7.org/fhir/administrative-gender"

  genders = "http://hl7.org/fhir/ValueSet/administrative-gender"

  

  print(bool(fhir.validate_code(genders, "female", gender)))

  print(fhir.validate_code(genders, "femme", gender))

  print(bool(fhir.validate_code("(%s)(female;male)" % gender, "other", gender)))

  print(fhir.lookup(gender, "female").display)

  print(fhir.subsumes("http://terminology.hl7.org/CodeSystem/v3-ActCode", "AMB", "_ActEncounterCode"))

  print(fhir.translate("female", gender, target="http://terminology.hl7.org/CodeSystem/v2-0001"))

  

  # True

  # CodeCheck(http://hl7.org/fhir/administrative-gender|femme: not held; Unknown code 'femme' in the CodeSystem 'http://hl7.org/fhir/administrative-gender')

  # False

  # Female

  # subsumed-by

  # [Match(equal http://terminology.hl7.org/CodeSystem/v2-0001|F)]

stage is the first half alone: it says what would be created or changed, and writes nothing until you commit. A correction can be said as the FSH rules that change, laid over the stored resource. The trail is a table SQL reads.

  import os

  import tempfile

  

  from agentfhir import FhirError

  

  store = os.path.join(tempfile.mkdtemp(), "clinic.db")

  a1c = {

      "resourceType": "Observation", "id": "a1c-1", "status": "final",

      "code": {"coding": [{"system": "http://loinc.org", "code": "4548-4"}]},

      "subject": {"reference": "Patient/ann"}, "effectiveDateTime": "2025-03-01",

      "valueQuantity": {"value": 9.4, "unit": "%", "system": "http://unitsofmeasure.org", "code": "%"},

  }

  

  written = fhir.write([patient, a1c], data=store, reason="first load", agent="intake desk")

  print(written.versions)

  

  try:

      fhir.write(dict(a1c, id="a1c-2", status="finl"), data=store)

  except FhirError as refused:

      print(refused)

  

  # ['Patient/ann/_history/1', 'Observation/a1c-1/_history/1']

  # Observation/a1c-2: Observation.status: code `finl` not in required value set http://hl7.org/fhir/ValueSet/observation-status (did you mean `final`?); it holds amended, cancelled, corrected, entered-in-error, final, preliminary, registered, unknown

With a project, what is written is held to the project’s profiles too.

7 With pydantic, and other model libraries🔗

Values are FHIR JSON, and you can give objects instead: anything that writes itself as JSON goes in as it is (a pydantic model, so fhir.resources and models of your own; a dataclass; fhirclient’s models). model= gives an answer back as objects.

  change = fhir.stage(fsh="""

  Instance: Observation/a1c-1

  * status = #amended

  * valueQuantity = 9.1 '%'

  """, data=store)

  print(change.changes)

  print(change.commit("corrected against the lab's report").versions)

  

  trail = fhir.sql("SELECT type, id, versionId, agent, reason FROM trail ORDER BY type, id, versionId", data=store)

  for row in trail:

      print(row["type"], row["id"], row["versionId"], row["agent"], "-", row["reason"])

  

  # [{'action': 'update', 'changed': ['status: "final" → "amended"', 'valueQuantity.value: 9.4 → 9.1'], 'resource': 'Observation/a1c-1'}]

  # ['Observation/a1c-1/_history/2']

  # Observation a1c-1 1 intake desk - first load

  # Observation a1c-1 2 fhir-api - corrected against the lab's report

  # Patient ann 1 intake desk - first load

A table’s rows become objects of a model whose fields are its columns, and a search’s rows the resources behind them:

  from fhir.resources.R4B.humanname import HumanName

  from fhir.resources.R4B.patient import Patient

  

  ann = Patient(id="ann", gender="female", birthDate="1980-02-28", name=[{"family": "Lee", "given": ["Ann"]}])

  print(fhir.fhirpath("name.given", ann))

  print(fhir.validate(ann).ok)

  print(fhir.fhirpath("name", ann, model=HumanName)[0].family)

  

  made = fhir.fsh("""

  Instance: bo

  InstanceOf: Patient

  * birthDate = "1990-01-01"

  """, model=Patient)

  print(type(made[0]).__name__, made[0].birthDate.year)

  

  # ['Ann']

  # True

  # Lee

  # Patient 1990

pydantic checks the shape a model declares. FHIR asks more: a code its value set holds, the rules of the base specification, whatever a profile adds. agentfhir.pydantic runs the toolkit’s validation, and FHIRPath, where pydantic runs its own. Valid() and Holds(expression) annotate a field of any model; checked(Model, profile) answers a class every object of which is held to a profile. What is wrong is a pydantic ValidationError, one error for each FHIR issue, its loc the element:

  import datetime

  from typing import Optional

  from pydantic import BaseModel

  

  class Born(BaseModel):

      id: str

      born: Optional[datetime.date] = None

  

  print(fhir.view("SELECT id, birthDate AS born FROM Patient", [patient]).to_models(Born))

  print(fhir.search("Patient?gender=female", [patient]).resources(model=Born)[0].id)

  

  # [Born(id='ann', born=datetime.date(1980, 2, 28))]

  # ann

Each check is one call of the toolkit, so in a loop over thousands of objects use validate_each. An error’s loc is where it is in the resource, inside a datatype too (Patient.name[0].given[1] is ("name", 0, "given", 1)). The toolkit does not generate pydantic classes from a profile: the profile is enforced when an object is checked.

8 Many resources, and data you use more than once🔗

A call crosses to the toolkit’s process and back. So ask one question of many resources in one call: fhirpath_each and validate_each take a list and answer a list, in the same order.

  from typing import Annotated

  from fhir.resources.R4B.patient import Patient

  from pydantic import ValidationError

  from agentfhir.pydantic import Holds, Valid, checked, use

  

  use(fhir)                                   # the FhirContext these ask

  

  class Intake(BaseModel):

      patient: Annotated[Patient, Valid(), Holds("birthDate.exists()", "a birth date is required")]

      note: str = ""

  

  for given in ({"resourceType": "Patient", "gender": "florp", "birthDate": "1980-02-28"},

                {"resourceType": "Patient", "gender": "female"}):

      try:

          Intake(patient=given)

      except ValidationError as e:

          print([(error["loc"], error["type"]) for error in e.errors()])

  

  # a class every object of which is held to a profile: here one written in FHIR Shorthand

  Adult = checked(Patient, "Adult", project={"adult.fsh": "Profile: Adult\nParent: Patient\n* birthDate 1..1\n* name 1..*\n"})

  try:

      Adult(id="cy", gender="female")

  except ValidationError as e:

      print(sorted((error["loc"], error["msg"]) for error in e.errors()))

  print(Adult(id="cy", birthDate="1990-01-01", name=[{"family": "Ito"}]).name[0].family)

  

  # [(('patient', 'gender'), 'fhir_code_invalid')]

  # [(('patient',), 'fhir_invariant')]

  # [(('birthDate',), 'minimum required = 1, but found 0'), (('name',), 'minimum required = 1, but found 0')]

  # Ito

Data that several calls read is given once. load sends the resources (or reads the directory, or opens the store) and answers a handle that any call takes as its data. Nothing is sent or read again, a search’s index over it is built once, and a view over it is computed once for all the SQL you ask of it.

  patients = [patient, dict(patient, id="bo", gender="florp", name=[{"family": "Ng"}])]

  

  print(fhir.fhirpath_each("name.family", patients))

  for outcome in fhir.validate_each(patients):

      print(outcome)

  

  # [['Lee'], ['Ng']]

  # valid

  # Patient.gender: error: code `florp` not in required value set http://hl7.org/fhir/ValueSet/administrative-gender; it holds female, male, other, unknown

9 Files, warnings, and calls that take too long🔗

A resource may be given as a dict, as JSON text, or as the path of a file that holds it.

  clinic = fhir.load(data)

  print(clinic)

  print(fhir.view("SELECT id, birthDate FROM Patient", clinic).rows)

  print(fhir.sql("SELECT count(*) AS results, max(value) AS highest FROM results", project=views, data=clinic).rows)

  print(fhir.search("Observation?code=4548-4", clinic).column("resource"))

  clinic.close()

  

  # Data(2 resources)

  # [{'birthDate': '1980-02-28', 'id': 'ann'}]

  # [{'highest': 9.4, 'results': 1}]

  # ['Observation/a1']

When an answer was made without something in the data, the call says so with a FhirWarning, raised at your line like any Python warning. Here a time has no time zone, which FHIR requires, so the view has no value for it; the table keeps the sentence as its notes. A map says the same of a value in its source that it could not read. warnings.simplefilter("error", FhirWarning) makes such data an error.

  import asyncio

  from agentfhir import AsyncFhirContext

  

  async def main():

      async with AsyncFhirContext(workers=2) as tk:

          outcomes = await asyncio.gather(*(tk.validate(p) for p in patients))

          print([outcome.ok for outcome in outcomes])

          print((await tk.lookup(gender, "male")).display)

  

  asyncio.run(main())

  

  # [True, False]

  # Male

A table goes where tables go: to_pandas(), to_polars(), or CSV.

  import json, pathlib, tempfile

  

  folder = pathlib.Path(tempfile.mkdtemp())

  (folder / "ann.json").write_text(json.dumps(patient))

  print(fhir.fhirpath("name.family", folder / "ann.json"))

  print(fhir.validate('{"resourceType": "Patient", "gender": "florp"}'))

  

  # ['Lee']

  # Patient.gender: error: code `florp` not in required value set http://hl7.org/fhir/ValueSet/administrative-gender; it holds female, male, other, unknown

FhirContext(timeout=30) gives every call 30 seconds. A call that takes longer, or that you interrupt (Ctrl-C, a notebook’s stop button), stops the toolkit’s process: the call raises, the next call starts a new process, and data you loaded is loaded again by itself. Nothing an interrupted call was computing is ever taken for a later call’s answer.

10 How fast it is🔗

The toolkit is a compiled program, and it runs in a process of its own. That decides what is fast: work done inside one call is quick, and many small calls each pay for the crossing. The numbers below are from clients/python/bench/compare.py, which you can run; it also times two pure-Python libraries on the same tasks. They do not do the same work (the toolkit’s validation checks codes and profiles, a model library’s checks shape), so read them as what each task costs, not as one engine against another.

  • Starting. Making a FhirContext takes about a millisecond: the process starts behind it. While your program does something else, the process loads what first calls need (the FHIR types, the definitions, the view engine, CQL). Asked straight away instead, a first call waits for what it needs. Counted from making the FhirContext: about 0.7 s to a first FHIRPath answer, 0.9 s to a first validation, 1.3 s to a first view, 2 s to a first CQL run. Asked after a pause of a few seconds, each first call takes milliseconds. (Those are from a source checkout; the executable a wheel carries reads all of its code when it starts, about 0.6 s more: 1.2 s to a first FHIRPath answer, 1.5 s to a first validation.)

  • The definitions, once a machine. Validation reads FHIR’s own definitions from the core package. The first time, the toolkit unpacks them into your cache directory (27 MB for FHIR R4, about a second more, once); later processes read from there. FHIR_CACHE_DIR names another directory; FHIR_PACKAGE_CACHE=0 keeps them in memory and writes nothing.

  • One call. About 0.1 ms for a FHIRPath expression over one resource, 0.2 ms to validate a small Patient. The resource is what costs, not the call: a US Core example with its narrative and profile takes about 0.6 ms.

  • Many resources. One call for all of them: one expression over 5,000 Patients takes 68 ms, validating them 417 ms. A loop of single calls costs the crossing each time. FhirContext(workers=4) shares such a list between four processes: 100 ms for that validation, for four times the memory.

  • Objects. An object costs what its library takes to write it as JSON: about 0.05 ms each for fhir.resources, a thousandth of a millisecond for a plain pydantic model, whose text goes into the call as it is.

  • The same data again. load it: a view over 5,000 Observations takes 152 ms with the resources sent in the call and 85 ms over loaded data; the same view asked again takes 7 ms (its rows are kept), and SQL over it about 1 ms.

  • Beside pure Python. Walking dicts in the same process, a compiled fhirpathpy expression answers one resource in 0.04 ms and a model library checks a Patient’s shape in 0.03 ms: for one small in-memory thing at a time they are quicker, and they check less.

11 Beside other FHIR libraries for Python🔗

Most Python libraries for FHIR do one thing: fhirpathpy evaluates FHIRPath, fhir.resources gives each resource a class and checks its shape. The other standard tools are programs in other runtimes that a Python program starts as a process: HL7’s validator (Java), SUSHI and GoFSH for FHIR Shorthand (Node), the CQL translator and engines (Java, JavaScript), the mapping engine (Java). This package is one install: FHIRPath, validation against an implementation guide’s profiles, terminology, FHIR Shorthand, CQL, the mapping language, SQL on FHIR views, search and a store. Three measurements, each a program in clients/python/bench that you can run:

  • How much of FHIRPath. HL7’s test suite for FHIRPath has 934 expressions with the answers they must give. The toolkit gives 932, compared with their types. fhirpathpy 2.2.4, counted right whenever its values equal the expected ones whatever their type, gives 788 (racket bench/fhirpath-suite.rkt).

  • What a check catches. A published US Core example with one mistake planted in it, eight kinds of mistake: a code outside its value set, an impossible date, an unknown element, a value of the wrong type, a required element missing, a rule of the base specification broken, an element the profile requires missing, a code the profile fixes changed. The toolkit refuses all eight, as HL7’s validator does; fhir.resources refuses three (python bench/validation.py).

  • What a check costs. US Core’s 230 published examples, each held to the profiles it claims, from nothing to an answer for every one: 2.1 s. HL7’s validator, a Java program run as a process: 49 s (35 ms a resource once it has loaded the guide; the toolkit: 1.2 ms).

The Python package’s README has the tables.

12 In a notebook🔗

%load_ext agentfhir.jupyter adds a cell magic for each language: %%fsh, %%cql, %%sof, %%fhir_sql, %%fhirpath, %%vcl and %%fml. What a cell defines stays for the cells after it, so a profile written in one cell is what a later cell validates against, and a view written in one is a table the next joins. A mistake is said at its line in the cell.

  %load_ext agentfhir.jupyter

  people = [patient, a1c]

  

  %%fsh

  Profile: AdultPatient

  Parent: Patient

  * birthDate 1..1

  

  Instance: cy

  InstanceOf: AdultPatient

  * gender = #male

  

  # AdultPatient.fsh:5:1: error: instance cy: Patient.birthDate: minimum required = 1, but found 0 (no rule of cy writes `birthDate`) (constrained by profile AdultPatient at line 3)

  %%sof -d people

  CREATE VIEW a1c WITH (status = 'active') AS

  SELECT subject.getReferenceKey(Patient) AS patient, value.ofType(Quantity).value AS percent

  FROM Observation

  

  #   patient  percent

  # 0     ann      9.4

-d names the variable that holds the data (resources, a path, or data you loaded) and -o a variable for the answer; %fhir lists what the notebook has defined. A table and a validation’s outcome show as HTML. It needs IPython, which a notebook has.

13 From a source checkout🔗

Without a wheel, the package looks for the toolkit in this order: the command the FHIR_API_COMMAND environment variable names; an executable bundled with the package; fhir-api on the PATH (the standalone build, ./build-tools.sh dist fhir-api); and raco fhir-api, which is there once Racket and the family’s packages are installed. From a checkout of this repository:

  pip install ./clients/python

  python3 -m unittest discover -s clients/python/tests

14 Another language than Python🔗

The Python package is a thin client. The work is done by a process, raco fhir-api serve (or the standalone fhir-api serve), that reads one request on each line of its standard input and writes one answer on each line of its output, as JSON-RPC 2.0:

  $ echo '{"jsonrpc":"2.0","id":1,"method":"fhirpath","params":{"expression":"name.family","resource":{"resourceType":"Patient","name":[{"family":"Lee"}]}}}' | raco fhir-api serve

  {"id":1,"jsonrpc":"2.0","result":{"values":["Lee"]}}

A request’s method is a function’s name and its params are the arguments by name. raco fhir-api functions prints every function; raco fhir-api functions --json prints them with a JSON Schema for each one’s arguments. That text is kept in this repository as clients/functions.json, and the Python client’s functions are generated from it (clients/python/generate.py): a client for another language starts from the same file. raco fhir-api call fhirpath '<json arguments>' makes one call from a shell.

A call that cannot be answered is an error with a code: -32601 for a function that does not exist, -32602 for arguments that are not the function’s, -32000 when the function failed, with data.diagnostics when the failure has a place in a source and data.outcome when it is a FHIR OperationOutcome. Problems in a source you gave to compile or translate are not errors: those functions answer their diagnostics.

15 Words used here🔗

  • FHIR: the standard for health data. A resource is one record (a Patient, an Observation) as JSON.

  • Profile: rules a kind of resource must keep, beyond FHIR’s own.

  • FSH (FHIR Shorthand): the language profiles and example resources are written in.

  • FHIRPath: a small language for reading values out of a resource.

  • CQL (Clinical Quality Language): the language of clinical rules and measures; ELM is what it compiles to.

  • View: a table defined over resources (SQL on FHIR).

  • Value set: a named set of codes; VCL is a short way to write one.

  • OperationOutcome: FHIR’s own resource for the result of a check, a list of issues.

  • Wheel: the file pip installs.

16 Limits🔗

  • The toolkit has no resource classes of its own. Values are JSON, and objects of a model library are converted on the way in and out.

  • A process reads one version of FHIR, 4.0.1 or 5.0.0. FhirContext.r5() is a second process.

  • Numbers pass through JSON: a decimal written 1.50 arrives as 1.5.

  • A wheel carries the FHIR R4 and R5 core packages. Any other implementation guide is given by its package file.

  • write and stage write to a SQLite store or a directory of FHIR JSON, not to a FHIR server. A stage is kept by the process that made it: commit it from the same FhirContext.

  • Wheels are built for Linux and macOS. Windows has not been built.

  • A table defined over a large SQLite store is computed again by each new process: for that, use a workspace.

17 How it is tested🔗

The server’s functions are each called as a client calls them, in every language, in fhir-api/tests (among them a process for FHIR 5.0.0). The Python package’s tests (clients/python/tests) hold its generated functions to the table and call every method against the server; they are run again against a built wheel, in a clean environment with nothing else on the PATH. Every example on this page is run by a test and compared with the output shown, the notebook cells in an IPython shell.
