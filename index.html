fhir: FHIR’s languages and tools🔗

FHIR’s specifications as #langs: a profile, a value set, a quality measure, a mapping or a query is a file in its own language, checked when it compiles, and a value a Racket program can use. Around the languages sit a validator, a terminology service, servers generated from Implementation Guides, and command-line tools that report every problem as file:line:col.

1 The languages🔗

language

  

you write

  

file

  

run it

fsh

  

profiles, extensions, instances, value sets (FHIR Shorthand)

  

.fsh

  

raco fsh check ig/

cql

  

clinical logic and quality measures (CQL)

  

.cql

  

raco cql lib.cql –data patient/

fml

  

maps between structures (FHIR Mapping Language)

  

.fml, .map

  

raco fml map.map –transform in.json

vcl

  

a value set's compose as one expression

  

.vcl

  

raco vcl expr.vcl

sql-on-fhir

  

tabular views over FHIR data (ViewDefinitions)

  

.sof

  

raco sql-on-fhir run view.sof data/

fhir/r6

  

a resource as a form, checked as it compiles

  

.fhir6

  

racket patient.fhir6

fhirpath

  

expressions over resources (a library, no file type)

  

  

raco fhirpath ’name.given’ p.json

Every file is a Racket module: (require "profile.fsh") gives the compiled resources, (require "screening.cql") a procedure over a patient’s data, (require "intake.fml") the map as a function. A mistake is reported where it is, in the file, when the module compiles.

2 Start here🔗

The packages are not on the Racket package server yet. Clone the repositories side by side and install from source (Racket 8.10 or later):

git clone https://github.com/oloveluck/fhir      # also: fhirpath vcl cql fml fsh sql-on-fhir fhir-examples

raco pkg install --link --auto fhir/fhir fhir/fhir-spec fhirpath vcl fhir/fhir-tx fhir/fhir-validation cql fml fsh fhir/fhir-server fhir/fhir-lsp fhir/fhir-mcp sql-on-fhir fhir-examples

Then one of these, each a few lines:

  • Write a profile and check an example against it: a .fsh file, then raco fsh check. The problem is positioned on the FSH line that caused it. Start with the fsh quick start.

  • Validate a resource: raco fhir-validate patient.json, or against a profile with the IG’s package in context (fhir-validation).

  • Serve an Implementation Guide: raco fhir-server serve-ig hl7.fhir.us.core, a whole server from the package, every write validated (fhir-server).

  • Run a measure: a .cql library over a directory of patient resources (cql).

  • See them together: fhir-examples/screening, one program composed of seven language files (fhir-examples).

  • In your editor: raco fhir-lsp is a language server for all five languages; the fhir-lsp page has the three-line setup for VS Code, Neovim and Emacs.

  • For an agent: raco fhir-mcp offers every FHIR operation and the languages’ checks as MCP tools (fhir-mcp).

3 The other packages🔗

This repository holds the foundation and the tools; each language is a repository of its own.

  • fhir: the typed node model, JSON in and out, the R4, R5 and R6 towers, #lang fhir/r6, StructureDefinition tooling, FHIR operations as procedures, diagnostics. raco fhir.

  • fhir-spec: the HL7 packages the tools read (core R4, R5, R6 and the IGs the tests use). Data only.

  • fhir-tx: the terminology service, $expand, $validate-code, $lookup, $translate over any FHIR package. raco fhir-tx.

  • fhir-validation: the validator. raco fhir-validate.

  • fhir-server: servers generated from IGs, #lang fhir/capability, the HTTP server and SQLite store. raco fhir-server.

  • fhir-lsp: a language server for the five languages, so an editor shows each problem as you type. raco fhir-lsp.

  • fhir-mcp: a Model Context Protocol server, so an agent can validate, expand, transform, compile and check through the same tools. raco fhir-mcp.

  • fhir-examples: worked examples and raco spec-bench, a benchmark for writing profiles from prose.

4 How the pieces fit🔗

  • One value model. Every language produces FHIR resources as JSON or typed nodes, so the output of one is the input of another: an FSH profile validates what an FML map produced; a CQL library runs over the same resources a SQL on FHIR view reads.

  • Operations as procedures. $validate, $expand, $transform, $evaluate-measure and the rest are applied by name with keyword arguments and threaded with ~>; the same values are served over HTTP by fhir-server.

  • The module system is the registry. Requiring a .fsh, .vcl, .fml or .cql module registers what it defines (profiles, value sets, maps, libraries), so anything that resolves by canonical url finds it.

  • Terminology. Codes are checked when a resource form compiles (required bindings that expand offline), when a resource is validated (through the terminology service when given one), and at run time by the service itself. CQL takes value set expansions as data; FSH records bindings and checks no codes.

  • One diagnostic shape. Every tool reports file:line:col: lang phase severity: message with the source line and a caret, or the same as JSON or an OperationOutcome (--format json|outcome), so an editor or an agent can read it.

5 Limits🔗

Each document ends its usage section with a Limits list taken from the code. The largest: nothing reads or writes XML; resource forms exist for R6 only; the server has no chaining, conditional requests or SMART; the validator checks no references or extension contexts and leaves invariants off; the terminology service cannot see external code systems such as SNOMED CT; CQL scores proportion measures only; FML runs every transform but dateOp, escape and pointer; FSH reproduces most but not all of what SUSHI writes for two real IGs.
